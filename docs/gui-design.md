# GUI 设计规范

串口工作台采用紧凑的桌面工具布局。将主要空间留给当前连接的收发数据、协议结果和图表。让用户在发起操作之前看清目标，在操作之后看清真实结果。规范适用于 M0–M6 的桌面窗口、配对浏览器、内置工具、独立插件视图、首启、更新和随包安装界面。具体页面示意见[界面草稿与场景](./ui-design.md)。

## 用户已明确的偏好

- **紧凑、齐整、稳定。** 保持 M0–M2 工作台的紧凑结构。统一控件高度、对齐线、横纵边距、字体和字重、边框、换行与排版。使用一致的留白和基线，给串口内容留出主要空间。M3–M6 的工具窗、配置和结果页沿用工作台的字号层级、控件对齐、颜色语义和反馈位置。
- **先画草稿。** 新增界面或实质重排之前先画宽、窄两版，说明控件、尺寸、排列、滚动、操作顺序和状态反馈，对照后再写代码。
- **连接与发送常显。** 工作台顶部保留工作区、COM 选择、参数和连接入口，底部保留当前草稿和发送，中央接收区独立滚动。发送按钮与草稿框顶边对齐并等高。常用动作在足够宽时按功能分组显示，空间不足时把次要动作放入共享菜单，连接与发送入口继续可达。
- **重复说明从主区移走。** 录制、设备、任务和诊断工具直接呈现任务内容。频繁使用的图标按钮保留可访问名称和提示。与当前设备、状态或任务相关的参数和证据进入相应详情或高级区，常用入口保持紧凑。接收区内的单行统计和时间戳保持固定位置，原始回执通过详情展开。
- **发送区给出准确的字节事实。** 草稿框右下角显示只读的最终发送字节数。文本与 HEX 模式在原草稿转换并保持字节语义。非法 HEX 或无法按当前编码转换时，保留原稿和原模式并说明原因。
- **表单与告警各有固定位置。** 参数窗采用可直接输入的波特率组合框、统一选项和标签列，最近有效串口参数按设备恢复。告警使用右下角共享通知，模块日志留存技术详情。提示、搜索和回执浮层出现时保持主工作区几何稳定。
- **保留外观与阅读习惯。** 主标题栏、侧栏和工作面跟随同一主题与皮肤。保留用户可选字体、壁纸、透明度和减少动效设置。默认收纳导航，恢复用户保存的展开状态。侧栏折叠、拉宽和主题切换应保持内容位置、焦点和输入响应。
- **用中性的界面框架衬托工作内容。** 收窄 COM 选择和工具按钮。侧栏选中采用中性材质，文字输入只有清楚的一层焦点边界。给主操作、当前连接及危险确认保留各自的强调方式。草稿标签、菜单和图标保持一致的图形语言。

完整范围、一致的设计语言和先画草稿来自本轮要求。连接、发送、告警、侧栏和外观的细节来自早期用户逐项反馈。#77 记录这些原则在各界面的实现。 [紧凑工作台反馈](https://github.com/YanChao001/serial-workbench/blob/1154b89f3b6eb59a1668bcef9c2bc6b245c88fc3/docs/ui-review.md) · [界面交互补充反馈](https://github.com/YanChao001/serial-workbench/blob/97ccd7b373068db972d93703d219eaf950f9c3d5/docs/ui-review.md) · [M0–M6 统一设计](https://github.com/YanChao001/serial-workbench/pull/77)

## 从历史改动归纳的设计取舍

- **优先展示操作对象和业务数据。** 连接、观察、操作各有固定位置。读数、字段、字节范围、报告和图表需要能回到来源。结果贴近输入，进阶诊断通过可展开、可复制的详情进入。
- **密度靠布局控制。** 使用共用刻度、分组间距、共享控件和独立滚动，为同类任务保留相同的阅读顺序。工具表单和设置可以降列或纵排，主操作随内容空间收敛。
- **视觉反馈跟随真实状态。** 连接按已确认会话着色。权限以作用中的目标为准。接纳、运行、等待停止、结束、失败和无法确认分别呈现。阶段状态、证据和重试跟着对应操作。
- **外观可配置，控件语义统一。** 主工作面的材质跟随现有皮肤和阅读保护，平台特有的系统控件保留原生行为。不同语言、密度与主题共用同一套交互层级。
- **交互连续性属于设计质量。** 打开搜索或菜单时，正文框的可视位置应稳定。查看历史期间维持原滚动位置，用户通过返回最新入口恢复跟随。切换主题、关闭弹窗或更新状态时，保留可继续编辑的焦点、选区或草稿。大文本用实际键入验证响应，布局改动用尺寸和位移检查支持截图结论。

这些取舍来自项目中反复出现的实现和复验。参数、布局与主题的具体值引用现行共享代码。 [工作台基础](https://github.com/YanChao001/serial-workbench/pull/59) · [M0–M6 统一设计](https://github.com/YanChao001/serial-workbench/pull/77)

## 先设计后编码

1. 写下用户从哪里进入、当前目标、必做任务、结果以及返回路径。使用真实标签、典型设备数据和有代表性的长度。
2. 画宽、窄两版。标出可用宽度、共同对齐线、同高度控件、长内容和页内滚动、主要操作的位置，以及侧栏展开或字号变大时的降列顺序。
3. 标出正常、空、加载、权限不足、失败、撤权和晚结果等适用状态。列出键盘顺序、初始焦点、关闭返回、已接纳任务与未保存更改的归属。标出通用控件或样式的来源，以及操作后要核对的状态或回执。
4. 按草稿复用现有外壳和控件。在现有组件上补齐共同变体，保留调用兼容。PR 附草稿和实际结果，注明验证窗口、语言、主题、业务结果与证据范围。 [页面草稿与自审](./ui-design.md#交付前自审) · [贡献流程](../CONTRIBUTING.md)

草稿至少能回答三个问题。窄且矮的窗口先收起哪些辅助控件。长英文标签、文件名和运行错误分别在哪里阅读。确认或取消后，操作者在哪里接着操作。记录实际字段名和相对尺寸，注明必要的滚动区与锚点，使评审能直接用草稿检查实现。

重排 M0–M6 的既有页面时，先记录当前界面中可复现的问题，例如同行控件高度不齐、长标签挤出按钮、窄窗出现整页横滚。改前和改后使用相同的窗口、语言、主题与测试数据。从 M0–M2 已合入的工作台或最近的同类工具选参考界面，对照字号层级、控件尺寸、焦点和反馈位置，并验证原有入口与键盘操作。如果共享控件需要新变体，在草稿里说明共用场景和选用条件，评审时同时检查旧调用方。

## 布局模式

| 场景             | 布局与行为                                                                                                                                                                                                                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 应用外壳和导航   | 复用 AppShell、HashRouter、窗口偏好及命令入口。标题栏系统控件、拖拽区及可点击区域边界分明。窄标题栏把菜单按原分组合并，浏览器页选择留在同一行。折叠侧栏的图标基线与命中区域稳定，保留名称、选中态、提示和键盘调宽。                                                                                                                  |
| 工作台           | 顶部连接与当前会话，中央接收、协议结果或图表，底部编辑和发送。连接栏、收发工具栏和正文对齐。系统工作区名称跟随语言，用户命名原样保留，载入时保持稳定位置。上下文菜单、搜索、告警、回执与临时预览用本区预留位或共享浮层。保持接收滚动范围与发送可达性。阅读历史、主动冻结和恢复跟随具有各自的控件或状态。                             |
| 工具窗与设置     | 按目标、字段、预览、结果、操作组织。宽窗统一标签列与控件列，窄窗标签在各自控件上方。相邻输入、下拉、文件选取和同行按钮使用相同级别的高度。短窗的工具正文负责纵向滚动。草稿标明主操作随正文还是放在固定底栏，两种方式均须在窄短窗可用键盘触达。设置搜索定位真实控件，表单状态留在所在字段或组。                                       |
| 数据、报告和详情 | 字节、图表和结果表占主列，统计、来源和导出按空间放侧列或移到结果之后。宽表、HEX 和图表需要横向浏览时，在数据区内横滚。正文保持纵向滚动。时间、单位、精确数值和定位范围有明确归属，技术标识放入可阅读、可选择、可复制的详情。                                                                                                         |
| 配对、插件与原生 | 配对和接管显示生效权限、具体设备及影响，弹窗关闭归还焦点。插件壳复用中英、明暗与加载、停止语义，插件内容准备后接管正文。原生对话框沿用系统布局和交互，应用接回所选状态。文件对话框确认后接回所选文件，取消时保留原选择，关闭后把焦点交回浏览按钮或仍可操作的相邻入口。安装和卸载沿用系统焦点顺序，并在确认前说明本次影响及数据去向。 |

断点由实际容器决定。窄窗、较矮窗口、展开侧栏、大字体和长标签叠加时，先保证顺序、完整内容和主操作可达，再调整列数。普通文本和错误自然换行。对路径、哈希及长文件名提供完整读取或复制入口。 [应用外壳](../src/layouts/app-shell.tsx) · [工作台样式](../src/features/workbench/workbench.css) · [场景草稿](./ui-design.md)

**常见工具的布局决策。**

- Modbus、RFC 2217 等参数密集的工具，先呈现会话、目标和模式。宽窗按语义把连续字段放在共享列上，窄窗沿同一顺序改为单列。校验提示贴着需要修正的字段，报文及例外结果在独立结果区阅读。按[实际 Modbus 入口及宽窄草稿](./ui-design.md#modbus-工作台入口与宽窄草稿)区分离线编辑、事务、寄存器与从站。
- 文件、录制和回放工具共用文件行和最近状态。文件名过长时保留全文读取入口。主操作表明是发送、录制还是只读回放，覆盖等有影响的动作说明目标，操作期间保留可见的进度和实际终态。
- 从下拉菜单打开工具窗，弹层接管焦点。工具窗内打开详情后，每次 Esc 关闭一层。先回到详情按钮，再关闭工具窗并回到菜单触发按钮或仍可操作的相邻入口。复验菜单退出动画结束后的焦点及键盘路径。

## 控件、文字与材质

- **统一来源。** 使用共享 Button、Input、Select、Dialog、Popover、Tooltip、表格、页签和通知。普通表单沿用 Input、默认 Button 和默认 SelectTrigger。紧凑次操作沿用已有 `sm` 或 `icon-sm` Button、`sm` SelectTrigger 与容器密度，同行控件按容器尺寸拉齐。共享 CSS 定义字体、半径、尺寸、边框和状态。 [共享控件](../src/components/ui/) · [控件样式](../src/styles/control-styles.css)
- **尺寸、对齐和间距引用现有刻度。** 工具栏沿用 `--app-chrome-height` 与 `--app-toolbar-control-size`。工具窗字段沿用 `--workbench-field-columns` 和 `--workbench-field-gap`，内部复用该窗的留白与对齐线。设置沿用已有设置行或表单变体。标题、说明、字段、错误及操作条按组对齐。按钮和单行控件核对高度、左右边界与文字基线。多行内容按其阅读空间定义高度。 [应用刻度](../src/index.css) · [工作台字段刻度](../src/features/workbench/workbench.css)
- **材质表达用途。** 普通面板用 `panel`，输入和选择用 `control`，浮层用 `popover`，长正文与编辑区用 `reading`，关键错误用 `solid`，图表与图像用 `artwork`，纯布局组用 `transparent`。复合编辑或分组优先由外层承载一个材质与焦点。普通分组用间距表达，独立操作区用清楚的边界。透明度及实体回退沿用共享材质公式。 [主题与透明度](../src/styles/surface-tokens.css)
- **层级使用同一字体体系。** 应用界面继承 `--app-font-sans`，输入和下拉沿用 `--control-input-font-size` 与 `--control-input-line-height`。标签与正文从所在表单继承字号和字重。终端、精确偏移和字节按用途使用用户终端字体或 `--font-mono`。统计列用 `font-variant-numeric: tabular-nums`，单位就近出现。标题、导航和控件分别承担一件事，同一操作的命名贯穿入口、确认和结果。 [应用字体与样式入口](../src/index.css) · [中英文入口](../src/i18n/registry.ts)
- **状态通过语义表现。** 主要动作复用主题主色，次动作使用共享次级样式，危险动作在明确确认处强调。选中、悬停、焦点、禁用和错误都有可辨状态。方向、连通性、序列和告警同时给出文字、标记或形状。在明暗、透明壁纸、高对比及缺少模糊能力时保持清楚的阅读层。 [应用材质使用](../src/styles/app-surfaces.css)
- **动效回应操作。** 使用已有交互动效表达展开、切换及确认，侧栏/主题切换保持布局稳定，减少动效时保留完整操作和静态反馈。持续动效按窗口可见性和用户偏好暂停。 [动效生命周期](../src/hooks/use-motion-activity.ts)

## 交互状态与可访问性

- **按任务区解释。** 在读取、运行、失败和重试的位置说明发生了什么和用户能做什么。普通短操作在原入口反馈，详情进入模块日志。字段问题就近显示，需全局提醒的故障复用共享通知并对同一故障去重。独立录制、传输和自动化任务在任务面板保留进度、停止和回执。可继续查看的上次成功内容保留原归属，并标明这次失败。
- **按当前目标处理异步。** 取消尚未确认的操作时保留选择或草稿并归还焦点。取消等待结束当次等待。已接纳的独立任务由原任务项呈现进度、停止请求和实际终态。晚结果只有在设备、会话代次、工作区、文件和权限等归属仍匹配时才能更新当前界面。查询失败时，可在同一归属和有效权限下保留上次成功结果并标明本次失败。发送区字节数按正文、行尾和校验计算，并与实际提交字节核对。
- **按键盘走全流程。** 字段有可见 label，提示文本给示例。图标按钮具有名称，装饰图标隐藏于辅助技术。下拉、菜单、表格和弹层支持键盘、IME、清楚焦点及合理的 Esc 返回。编辑层消失时把焦点交回能继续操作的位置。状态具备可读名称及必要的无障碍宣告。
- **按文案定位问题。** 中英都使用明确的动作动词和一致术语。错误说明作用范围和修复或重试入口。长错误、内部标识和原始回执放入可展开详情。全局通知使用统一宽度、正文、长文换行和堆叠规则。 [通知实现](../src/lib/notifications.tsx) · [状态保存组件](../src/components/settings-persistence.tsx) · [开发规范](./conventions.md#界面)

**连接与任务的状态样例。** 打开串口得到接纳后显示正在连接，匹配该设备和会话代次的成功结果及会话状态后再用已连接样式。请求停止文件任务后保留进度，显示等待停止并从同一任务查询终态。状态无法确认时呈现其所属任务和可重新查询的入口。切换会话后按原任务归档回执。

## 验收与证据

| 检查       | 交付时应有的证据                                                                                                                                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 结构与尺寸 | 对照草稿实测目标窗的控件高度和基线、内外边距、断行、内容滚动边界、主按钮命中及内容首屏。覆盖典型宽窗、窄且矮的窗口，以及宽侧栏和大字体组合。                                                                                                                      |
| 外观与文案 | 实际查看有代表性的截图或视频。覆盖中英、明暗、透明壁纸、长名称与错误，按影响检查强制颜色、缺少模糊和减少动效。用典型真实数据做视觉自审，再用极端输入验证边界。                                                                                                    |
| 操作与异步 | 用键盘完成主流程。验证菜单开关及焦点返回、组合框输入、禁用说明、读写权限、失败重试、长数据、停止及终态。动作发生后的可见状态与真实回执一致。                                                                                                                      |
| 平台证据   | 日常 GUI 用无头 `pnpm test:ui`。涉及原生窗口、系统对话框、剪贴板、实机连接或安装器时，按适用平台在独立环境或用户安排的前台时段验收。按平台记录候选提交、画面、状态、已跑范围和待验范围。 [桌面边界](./testing.md#桌面边界) · [原生桌面](./acceptance.md#原生桌面) |

文件行用长英文文件名和无空格长文件名压窄验收。核对完整读取和复制、操作按钮可达，以及正文和弹窗边界。安装或卸载在适用原生窗口检查 Tab、Shift+Tab、可见焦点、确认和取消的真实结果，以及默认选项下的数据去向。

持续接收时观察时间戳、分隔线和正文边界是否跳动，向上查看历史、主动冻结和返回最新分别实测。打开通知、搜索和详情时比较操作前后的正文位置。启用完整动效后连续点击主题切换，核对每次点击的结果、选区和焦点。对于大文本、密集事件和高缩放，用连续输入及滚动复测响应。 [交互稳定性复验](https://github.com/YanChao001/serial-workbench/pull/46)

浏览器强制颜色可使用现有的 `page.emulateMedia({ forcedColors: "active" })` 场景。原生高对比随实际系统设置核验。无头画面记录浏览器覆盖范围，原生窗口、系统对话框和安装器按平台证据记录。

布局用例里的窗口尺寸是测试输入，产品断点仍取自实际布局与共享设置。诊断用例的 410×460 与 1240×760 分别覆盖窄短窗和宽窗。标题栏和工作台另有各自的压力窗口。 [诊断窗口用例](../e2e/browser/diagnostics-layout.spec.ts) · [桌面界面用例](../e2e/browser/desktop-ui.spec.ts) · [工具窗用例](../e2e/browser/workbench-tool-layout.spec.ts)
