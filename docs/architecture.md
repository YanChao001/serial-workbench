# 产品架构

2026-11-13 补充：授权仓库按持久 revision 复用已解析快照，每次读仍核对数据库 revision；未改变的授权不重复保存或使正在交付的回复失效。窄范围/Host 范围的后续覆盖仍按原顺序判定。单客户端规则上限为 4096，全局为 32768，不把精确设备或会话授权改成全 Host 授权。

工作区删除使用 `WorkspaceDocument.archived`：保存原件与移出目录在同一事务提交，已删除工作区拒绝后续覆盖，默认工作区不可删除。普通读取不会将已删除文档重新登记；复制、导入和导出清除该生命周期标记。删除不关闭串口或清除发送草稿。

本文描述当前源码结构。预期功能见[需求](./requirements.md)，实现与验收缺口见[进度](./progress.md)；Node、浏览器连接与 LAN 的后续设计见[规划](./plan.md)和[契约](./contracts/README.md)。

## 运行结构

桌面、CLI 和 MCP 经本机 IPC 连接同一 profile 的独立 Rust Host。Host 统一持有设备、发送仲裁、原始流、录制、操作和共享文档；关闭窗口或客户端后，已接纳任务可以继续。桌面仅管理本地窗口、系统交互和呈现。

| 位置                         | 职责                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| `crates/core/`               | 公共领域模型、wire DTO、错误、能力目录与导出契约              |
| `crates/ipc/`                | 当前用户本机传输、帧、发现、实例锁和受保护身份存储            |
| `crates/host/`               | 设备、流、TX、任务、录制回放、权限及共享文档服务              |
| `crates/client/`             | Host 的 Rust 认证、连接、启动与 RPC 客户端                    |
| `crates/cli/`、`crates/mcp/` | 命令行和官方 MCP SDK 适配器，共用 Host 能力                   |
| `src-tauri/src/`             | Tauri 桌面组装、Host bridge、窗口、文件选择、媒体、恢复和更新 |
| `packages/contracts/`        | 从 Rust 导出的 TypeScript、schema、默认值及校验器             |
| `packages/host-client/`      | 不依赖 React/Tauri 的客户端投影、reader 和增量解码            |
| `src/features/workbench/`    | 工作台组件、布局、发送草稿及工具                              |
| `src/providers/`、`src/lib/` | Host/设置/未保存工作协调、门面和模型                          |
| `e2e/`                       | 浏览器与真实桌面测试源码；运行产物另存 artifacts              |

根 [Cargo.toml](../Cargo.toml) 管理全部 Rust 包和共享 profile，使用唯一的根 Cargo.lock。无头包能够独立构建和测试；`src-tauri/target/` 是配置的共享编译输出位置。

## 客户端入口

前端由 `main.tsx`、`App.tsx` 组装 Provider、HashRouter 和边界。路由、懒加载、预载、导航位置与布局统一在 [routes.tsx](../src/routes.tsx)，菜单、命令面板和快捷键复用 `src/commands/`。

设置项图标集中在 [settings-icons](../src/lib/settings-icons.ts)，设置页面、独立设置组件与命令入口共用该映射；搜索条目的 ID 受映射键类型约束，避免命令入口全部退化为通用齿轮或与页面分别维护。

首页为串口工作台，设置承载偏好、诊断与恢复，启动故障保留受保护的隔离入口。工作台顶部连接、中央接收、底部常显发送，参数和辅助工具就近展开；布局及无障碍约束见[界面规范](./conventions.md#界面)。

手写 TypeScript 通过 [tauri.ts](../src/lib/tauri.ts) 使用原生能力。门面检查运行环境；浏览器提供独立存储的界面预览。浏览器 fixture 只服务测试，不进入生产状态回退。Native 命令及 Host DTO 分别生成绑定，流程见[开发指南](./development.md#契约与功能接线)。

通用业务 JSON 与 schema 元数据分别使用 `JsonValue`、`SchemaValue`；递归反序列化按 JSON 节点类型直接分派，避免大投影和目录逐层尝试 untagged 分支。业务数字继续经过原安全整数校验，schema 数字仍允许小数；序列化、Rust 导出 schema 和 wire 形状不变。

内置动作目录的两个固定 schema 方言各生成一次，只读访问借用静态结果；Registry 按当前授权过滤后仅克隆返回页，MCP 复用固定 wire schema，动态可见目录与版本仍每次从 Host 获取。Native 状态帧统一在 SDK 的未知输入边界完整校验一次，订阅身份、缓冲预算与 ACK 分别保留。

桌面通过 Tauri 公开的 `Builder::invoke_system` 使用[单一 postMessage IPC](../src-tauri/src/ipc-transport.js)。原 fetch IPC 在页面重载取消回复时可能再次投递已接纳的调用；实际 Intel Native 场景与锁定版本脚本均已复现重复通道/相同 payload。单一路径保留 Tauri 的 invoke key、回调、headers、Map/字节/Channel 序列化及原生能力检查，不添加请求重放或放宽现有预算；代价是不用 fetch IPC 的二进制传输优化。接口兼容由脚本回归与四目标原生场景共同验证，不能用只读查询共用回复掩盖修改操作的重复执行。

传输使用 Tauri 基础脚本创建的内部容器。认证占位符只出现在可执行表达式中：`Builder::invoke_system` 全文替换脚本，Z85 密钥可含注释终止符，若注释也出现占位符会随机破坏整段初始化。密钥仍由闭包持有，投递函数源码不暴露其值；合法合成密钥的初始化、认证和一次投递回归覆盖此边界，实际原生门槛见[当前进度](./progress.md#ipc-随机密钥注释缺陷)。

已认证连接与工作区元数据初始化分别管理。目录、设备列表及选中工作区文档到达后开放连接操作，避免草稿归属未恢复时发布空工作区；历史投影在后续初始化，不把其耗时计入设备可用门槛。首次或后续查询失败在工作区保留错误和重试入口，连接继续供设置等独立订阅使用；Host 启动失败、认证失效或实例代次变化才退休连接。重试查询不重新授权或重放修改操作，见 [HostProvider](../src/providers/host.tsx) 和[工作区控制器](../src/providers/host-controller.ts)。

连接构造只完成认证，各模块在建立订阅前读取所需目录。会话快照或订阅的 epoch 变化先退休该读者并有界重读 scope，不能仅凭 `EPOCH_MISMATCH` 清空整个连接；目录自身也可能因会话换代返回同码。目录分类及恢复耗尽时，通过原连接的独立只读 catalog 响应、完整身份和当前生命周期确认原实例仍有效，才保留为模块故障；未知或真实实例失效保持原错误。三次恢复预算归工作区所有者，成功建立订阅本身不重置预算；终态释放读者，晚结果隔离，明确重试可重新尝试，不自动重放打开或发送。

## 数据归属

已确认草稿的内存快照由窗口级 [ClientDraftsProvider](../src/providers/client-drafts.tsx) 持有，首次成功恢复及实际保存回执更新；组件重建时可同步读取，避免再次进入恢复提示。已访问的工作台路由另由缓存布局保留未保存正文和 DOM。首次失败不缓存空草稿，取消一个读取等待不取消其他等待者。保存始终读取最新 ClientState 并执行 revision CAS 与未来格式检查，取消等待后的实际回执仍更新缓存；旧读取不能覆盖新 revision。实现见 [client-drafts](../src/features/workbench/client-drafts.ts)。

工作台正在编辑的正文由自身的 [draft-store](../src/features/workbench/draft-store.ts) 同步持有，各视图独立；编辑区订阅当前视图的字符串，工作台外层只订阅脏状态变化。文本框保留浏览器原生编辑值，输入事件同步更新数据源；外部重置、格式转换或视图切换只在正文确实不同时于布局阶段写回，避免 React 每键同步 `defaultValue` 导致长文本重复排版，同值更新保留选区及输入法过程。保存动作现场取得最新快照，迟到的保存确认不清除后续编辑；放弃回到已确认快照。它不替代窗口级已保存草稿缓存或 Native CAS。权限预览在 [workspace-send-panel](../src/features/workbench/workspace-send-panel.tsx) 合并连续输入，新正文立即使旧参数的预检查失效，真实发送仍使用当前字节并由 Host 重新验权。发送工具栏只随格式、回执等实际依赖变化重绘，Text/HEX 转换读取草稿原文，保留浏览器文本框会规范化的 CRLF 等字节差异。

| 数据                                    | 权威与位置                                                                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 身份、授权、Operation、共享设置和工作区 | Host profile 下 `host-v0/state.sqlite3`，实现见 [storage](../crates/host/src/storage/)                                      |
| 客户端窗口偏好、图库引用和草稿          | Native `appConfigDir/client-state-v0.json`，按窗口保存，见 [client_state.rs](../src-tauri/src/client_state.rs)              |
| 桌面路由与窗口恢复元数据                | Native `appConfigDir/workspace.json` 及窗口插件管理的几何状态，见 [system_commands.rs](../src-tauri/src/system_commands.rs) |
| 更新镜像或禁用策略                      | `appConfigDir/deployment.json`；公钥仍固定在安装包内                                                                        |
| 原始录制和导出                          | 明确选择或登记的目标，由 Host 管理引用、内容 revision 和实际写入结果                                                        |
| 浏览器预览                              | 共享预览偏好用 localStorage；窗口 ClientState 用 sessionStorage，见 [client-settings.ts](../src/lib/client-settings.ts)     |

共享设置与工作区使用 revision CAS。保存只确认相应提交，冲突重读且保留草稿；窗口的日常标签调整不立即写入共享模板，显式保存才更新模板，其他窗口的运行布局独立。

工作区编辑器以视图设置和连接参数分栏组织控件，在窄容器下纵向排列。颜色复用共享选择器，视图图标的选择与标签渲染共用 [workspace-view-icon](../src/features/workbench/workspace-view-icon.tsx)。同一工作区草稿变化通过既有 `reconcileWorkspaceTabs` 更新标签属性，按绑定来源核对会话引用，并处理新增、删除及用户关闭的视图。

工作区文档保存视图与设备绑定、显示格式及连接预设；实际串口连接由 Host 会话持有，多个视图可以共享一个连接。打开编辑器时同步呈现当前窗口的串口标签快照，无需先执行另一项布局保存；首帧使用同一快照，随后登记本地编辑草稿。原本只持有会话的运行标签接纳为文档视图时核对实际 Host/设备并保留会话关联，新工作区或代次切换不接纳旧所有者的快照。保存及另存为均包含这些标签，新绑定从实际连接取得参数，已有编辑草稿中的预设保持权威，不能被正在运行的不同参数静默覆盖。顶部布局保存使用同一快照构建器，已关闭标签不写入本次布局。选择工作区不隐式打开或重配串口，关闭标签也不等于断开连接。

编辑器可直接添加离线串口视图、移除视图及克隆，配置方案不打开设备。新视图和克隆采用可区分名称；已有同名视图、绑定及运行标签统一经显示标签消歧，保留原始用户名称与内部身份。连接预设用于后续打开，正在使用的连接通过顶部连接参数工具修改。读取策略接入设备 owner 的读取预算，单轮合批预算最多 20 毫秒。Windows 首字节读取的空闲等待最多 2 毫秒，连续读块在该轮预算内汇总，已完成前缀先交付，后续错误由下一次读取报告。原生完成和调度使用独立余量，资源归还以实际完成为准。持续接收逐轮检查控制队列，空闲后恢复邮箱等待。缩小读取等待会增加空闲唤醒，写入等待是截止预算，重连间隔是初始退避，均不是正常收发的固定间隔。

本窗口明确打开连接的成功回执记录会话身份与 epoch，绑定于 Host/实例/连接 generation/actor/client 身份。克隆、另存为及工作区切换可沿用身份匹配且仍打开的本地连接，复用现有读取与发送权限，不重开设备、不为其他会话补授权；只在元数据中出现的会话不能据此接纳，代次变化清除或使证明失效。编辑器初始化保留已有连接预设，保存回执仅在内容匹配时清理对应编辑草稿，较新的输入继续保留。

工作区恢复的是视图及连接预设，视图与实际连接分开管理。所选视图绑定失效时，用户在顶部明确选择替代设备并连接，成功后使用原视图身份，保留名称、显示格式和发送草稿；接入已在另一标签显示的连接也先完成授权，不把连接按钮误作断开。活动视图使用设备 A 时，连接其他设备 B 新建或定位 B 的视图，保留 A；离线视图替换设备时沿用其预设，已打开设备的实际配置保持权威。连接前不凭元数据新增或切换标签，晚回执不得跨 Host/实例/连接身份接纳。匹配同一设备的视图共用实际会话和一份读取订阅；重连后一起换到新会话，保持当前选择。运行视图留存最近确认的设备及配置来源，用于旧会话元数据清理后的重连和布局保存，不提供收发权限；已关闭的会话不重订阅读取。替代绑定在显式保存布局或工作区时提交，其他视图和收藏预设保留原绑定。

工作区编辑、运行布局初始化与保存回执共用文档内容比较，忽略 JSON 对象键的排列及省略的 undefined 字段，保留数组顺序和实际字段差异。Native 序列化调整对象键顺序不能使保存后的文档重新变脏，也不能阻止匹配回执结清草稿。

录制清单与索引先写同目录候选并同步，再原子替换。Windows 使用标准库包含 FileRenameInfoEx 回退的替换路径，允许仍在读取旧件的合法共享读者；同一候选文件句柄保留到更名后再次同步。只读或禁止删除共享的目标仍明确失败；替换失败保留原件和候选，替换后的同步失败保留实际文件并返回错误，不伪造回滚。目录归档和新件发布继续禁止覆盖，见[录制契约](./contracts/capture-container-v0.md)。

ClientState 的偏好、草稿和图库共用窗口 revision。偏好保存遇到其他切片更新时，最多尝试三次并保留最新非偏好数据；若偏好本身已被修改，保留本地输入并要求明确重试，不自动覆盖并发偏好。

最近连接参数也属于窗口 ClientState，按 Host ID 与不透明设备 ID 保存，最多保留 128 组；COM 名称不作为身份或授权依据。有效的离线编辑自动持久，在线修改仅在全部字段具有匹配的实际应用回执后记忆。参数与偏好、草稿、图库复用同一 revision CAS，同目标并发修改保留输入并要求明确重试。参数保存失败纳入未保存工作协商，初次读取失败不虚构本地编辑；未来格式保持写保护。

打开串口时优先使用当前上下文的显式参数编辑，其次是所选视图的工作区绑定预设，再回退到最近连接参数与默认值；已打开会话的实际配置保持权威。局部连接参数以工作区、Host/设备、绑定及预设字段值隔离。切换工作区或重新选择工作区时重置局部显示格式和设备选择，按恢复视图的准确 Host/设备绑定定位端口；绑定不可用时要求明确选择，不能回退打开无关的首个端口。

工作区选择器通过 `workspace.list` 读取持久目录摘要，每页最多扫描 64 个条目，按元数据权限过滤，使用不透明游标继续；读取目录不选择文档或建立投影，也不逐项加载完整工作区。存储的 `workspace_directory` 只登记文档身份，名称与 revision 从权威文档读取；保存文档及登记目录在同一次 SQLite 事务完成。此前已保存的文档经成功读取后补登记，不登记只读探测产生的 revision 0 默认值。按标识打开仍作为辅助入口。

工作区选择器提供新建空白工作区、另存为、刷新及继续加载目录。新建和切换先完成未保存编辑协商，协商可调用保存，故只有协商结束后才能禁用编辑器。另存为包含当前工作区编辑草稿，使用新工作区标识及新视图/绑定身份，重映射收藏引用，不复制发送草稿或实际连接；成功提交副本后才结清原编辑草稿并切换。失败保留输入，已成功保存后的加载失败不重放保存，用户可从目录重新打开。组件取消只结束等待，不冒充持久操作回滚。

工作区空名称表示未命名，显示层使用当前语言的缺省名称或输入占位；所有非空名称均作为用户数据保留，包括字面值 `Workspace`。不通过名称文本或内部默认 ID 猜测、替换或迁移用户命名。

设置保存状态同时等待当前连接、已提交 revision 和本次重试对应的原生效果调用完成。磁盘提交成功但原调用仍在途时保持 saving，真实回执通过身份/revision 核验后才完成；旧连接晚结果不能结算新连接。效果失败保留错误与明确重试，不自动重放修改操作。

工作区及工具草稿的 scope 身份使用 [scope 键](../src/lib/host-scope.ts)按 scopeId 与 Target 固定字段生成，不依赖 JSON 对象字段顺序；查询、投影及原生命令可采用不同序列化顺序。Host attachment/epoch/generation 仍单独隔离，revision 更新不冒充目标切换。

操作故障由路由外常驻观察器消费已授权投影，首次附着的历史终态只建立基线。设备就绪与操作历史就绪分别表达；首份有效操作投影到达后才初始化通知基线，包括确实为空的历史，避免延迟加载的旧故障在启动时重新弹出。后续真实失败按执行 Host 与 Operation ID 在窗口内去重，通知与模块日志共用 512 项有界事件账本；元数据暂时失败不丢失已知待完成任务。普通 RPC 或界面等待失败不冒充操作终态，只有匹配的实际终态错误携带该操作身份。工具关闭不停止独立任务，也不阻止其后续故障通知。

设置、文档与发送的前台失败保留已核验终态的安全事件身份，与常驻观察器共用去重；新请求清除旧身份，不能用上次回执的错误码或严重级别解释新的 RPC 故障。设置页固定保留明确重试入口，不依赖通知是否先出现或仍在五秒显示期内。

每个窗口文档只有一个工作台发送区。通知按该区的实际尺寸避让，显式调整草稿高度或窗口大小时重新测量，卸载清理观察器与窗口样式；通知不参加正文布局。空通知只在已显示状态结束时关闭一次，后续数据刷新及空通知卸载不重复广播关闭事件，避免通知库同步刷新放大接收开销。纯说明 Tooltip 的内容及定位外层不参与鼠标命中，交互弹层保留原有点击行为。

共享 Tooltip 区分主动键盘导航与点击、Esc 关闭浮层后的恢复焦点；恢复仍回到入口按钮，但不因此自动打开提示。鼠标悬停保持既有延时，Tab/方向键导航仍立即提供说明。嵌套 Provider 共享一组文档输入监听，最后一个 Provider 卸载时清理，不为每个图标增加监听或渲染。

Native 显式设备连接核对原 `device.open` 调用、执行 Host、actor/request、完整 Target 与原 Operation ID 后，才在真实故障终态的 `HostError.details.operationFailure` 附加安全操作身份。原 OS 错误详情保留，RPC、读取、等待及取消错误不附该标记；前端只将经此边界核验的身份与操作投影去重。

图库保存 ObjectRef 与名称，当前背景属于共享设置；移除图库条目只移除元数据。媒体内容经受控协议读取，临时 URL 不进入共享文档。内置壁纸及 SVG 皮肤由资源清单维护，见 [wallpapers](../resources/wallpapers/README.md) 和 [skins](../resources/skins/README.md)。

旧软件 API、数据和插件格式不读取迁入。旧 `settings.json` 原件保留；当前共享偏好权威为 Host，Native 恢复对象为 ClientState。

## 生命周期与资源责任

实时参数变更通过统一消息通知反馈，不混入接收正文；原始配置边界继续保留用于解码、搜索和回放。通知与缺口共用按完整源身份保留的有界高水位，多视图及重开不重放旧消息；回放只呈现历史配置，不触发实时参数通知。侧栏初始收纳来自 Rust ClientPreferences 及其生成默认，前端不另设默认；已保存的用户展开选择继续恢复。

连接按钮依据实际会话状态展示。[操作观察器](../src/providers/host-action-observer.ts) 按完整输入独立续检并共享相同查询，窗口隐藏时停止新查询，过期、撤权及 epoch 变化立即清空观察；并发名额在真实读取结束后归还。到期检查按等待时间调度，慢续检不能反复抢占名额而使新输入饥饿。发送草稿本地即时更新，远端观察在短暂停止编辑后更新，空草稿不发送无效 TX 检查。连接、发送及会话参数/控制的明确拒绝仍禁用，短暂未知允许用户发起实际核验，不能将观察当作授权票据；工具目录未公开的动作明确禁用，提交时对当次完整输入重新检查，Host 接纳及实际执行继续验权。Native 已确认打开后，附带元数据查询的错误独立报告，不将实际打开改报失败。明确授权成功时允许同代仍在途的旧初始 Raw 读取拒绝后重新验权，保持原有界预算，不重放打开/发送，也不自动恢复真实源终止。

Host 工作区退休可以先于旧 React 渲染的被动效果注册。共享动作观察器对已退休或已取消的晚注册同步发布未知结果并返回空清理函数，不发请求、不恢复授权、不占检查名额或定时器；正常活动观察的容量错误和真实读取错误继续报告。该生命周期规则统一覆盖工作台、工具及控制面板，不在全局错误边界吞掉所有取消异常。

主题选择及已接受的远端主题即时应用，不使用会在截图与动画期间屏蔽原页面命中的整页 View Transition。完整动效下，本地切换通过独立旧外观层从标题栏按钮做 1050 毫秒的圆形展开，视觉层使用封闭 Shadow DOM、inert 和无指针命中，真实页面始终接收操作。快照限制节点及文本预算，省略离屏接收正文，固定接收行的实际高度并恢复滚动。视频仅复制当前帧。每次切换都从按钮重新向外扩散，连续点击即时替换上一层旧外观。动画判断依据最新逻辑选择与上一次选择的差异，主题即时提交。滚轮、其他点击、键盘、窗口尺寸/可见性变化、卸载及减少动效均清理视觉层。装饰失败或预算超限即时降级。日月图标保留独立短动效。远端接受的主题取消本地旧外观层后即时应用，主题缓存只用于首屏，Native 等待已接受的设置快照，共享同步不反向保存。命令只有真实返回异步任务时才持有执行标记至完成，同步命令当次调用即可归还。

操作详情、状态投影、Raw 读取/续额及指标属于自监控流量，不再为每次观察重发活动历史；显式查询继续记录活动，实际修改仍按 Operation 持久接纳及结算，原始 TX/RX 和回执不变。活动序列化与投影提交经既有有界阻塞执行器，不在异步 I/O 调度线程内遍历整份历史。接收快照与 ACK 即时推进，普通 Raw 数据仅合并短周期内的工作台订阅通知；错误、读者移除及其他状态变更立即刷新，工作区释放时清理待发通知。接收数据切片及行树在输入、权限更新时保持稳定，仅在源数据或显示偏好变化后重算；长列表由浏览器跳过离屏布局，保留完整字节与搜索定位。跟随滚动禁用浏览器锚定，以滚轮、键盘、触摸或滚动条的人工输入识别离开底部，不把内容重新排版的滚动事件当成人工滚动。

查看接收历史只停止自动跟随，不冻结数据和字节统计。此时保留有界显示缓存中已见事件的身份集合，新事件继续进入现有缓存，浏览器锚定保持阅读位置；用户向下滚到底部、End 键或“返回最新”恢复跟随，缓存裁剪和晚排版产生的滚动不退出历史。主动冻结及查找仍使用独立的有界显示快照。接收底栏保持固定单行，历史更新数量与返回最新合并为一个有边框的下箭头按钮，没有更新时显示“返回最新”；主动冻结仍显示“显示已暂停 / 待显示 N 条更新”。计数是当前缓存中的事件更新数，不代表串口协议帧数。跟随时，内容与视口尺寸观察合并为每帧至多一次定位，处理大行及离屏内容的晚布局；切换状态或卸载时清理观察器和待执行帧，旧回调不能改变历史阅读位置。

溢出接收区自动跟随时，在内容起始处补齐不足一个 CSS 像素的高度，再读取滚动高度定位末行，避免小数行高与整数滚动度量造成分隔线、时间戳逐帧摆动。补齐使用布局像素，不按设备像素比例另行舍入；未溢出时不添加补白。减少动效的动画、过渡策略统一在共享 `control-styles.css` 维护，普通过渡及延迟关闭，保留浮层动画原有终态机制，避免重复规则反而为所有元素启用短暂过渡。

Native 明确文档保存先检查该动作及参数的现有权限，缺权时才通过控制入口授权。反复保存主题不重复增加授权代次；普通读取、业务调用和订阅恢复仍不得补授权。Text 接收展示可合并同源、同配置且字节连续的相邻 RX 块，按有界显示长度分组；原始块、游标及时间不改写，HEX 保留原块，不能将显示分组当作报文边界。普通视图以本地毫秒时间显示原始 wall time，精确原值保留在语义元数据及 Raw 契约；TX 回执由发送方向图标按需展开。当前显示的确认发送和接收字节统计固定在接收框内部底部，内容区独立滚动，不作为设备应答或会话全量计数。

同 epoch 的权威 closed 状态会停止 Raw I/O，保留接收字节、游标及现有视图观察者，最后一个视图退出才释放缓存；closed 不因普通授权重建读者。远端 Raw 终态、游标、credit 或订阅建立返回指定关闭码或 HOST_BUSY 时，仅做一次最长 5 秒的 Control `session.get`；只有原 Host、实例、窗口代次、会话与 epoch 完整匹配、revision 不落后于最新已知投影且状态为 closed 才静默退休，并将该权威结果同步到会话状态，避免连接和发送控件仍按 open 判断。其他状态、查询失败和不确定结果保留原故障；本地批身份校验错误不进入此确认路径，也不通过消息文字推测正常关闭。Raw 回复校验失败的日志保留动作阶段与 CONTRACT_INVALID 分类，不记录回复正文。

操作投影的普通 delta 仅重读缺失或 revision 更新的详情，完整快照仍全量刷新当前权限可见性；后续 delta 不得跳过正在全量重新授权的条目。成功的操作预检续期只在允许状态变化时通知视图，错误保持完整发布。Raw 订阅的读者内存队列使用 Host 公布的上限，wire credit 另保持至多 1 MiB：队列、待确认帧和编码分配不能共用只按正文大小理解的额度。Raw ACK 携带上次 Host 会计确认的下一窗口额度，余量不足最大批次时才单独补额度；客户端核对回执的 ACK、额度与单调关系，不估算 JSON 大小或扩大窗口。接收搜索采用单遍匹配，保留下一结果和回绕首项；完整源身份、缺口及配置边界阻止跨源拼接。

Host 操作历史由 Store 变更通知驱动唯一投影任务发布；授权、平台效果及其他动作的执行和结算不等待历史列表重建。启动与最终关停仍等待对应投影完成。历史查询在 SQLite 中先提取摘要，再反序列化为 `OperationSummary`，不在显示路径反序列化完整发送正文或其他结果证据；保持活动操作优先、最近 256 条的范围、错误码优先级及结果引用隐藏。完整 Operation 和结果仍留在原存储，权限检查、操作查询及失败证据不依赖该显示摘要。

- Host、客户端、会话、视图和 Operation 各有身份与代次。切换 Host/目标、撤权或卸载后隔离旧结果；订阅处理 StrictMode、晚到完成和清理。
- 未保存工作由 `useUnsavedWork` 登记。离页、关闭、退出和安装更新复用协商；保存失败或用户取消时保留工作。
- 调用接纳与执行完成分别处理。停止等待不回滚已发生 I/O；按 Operation 终态和实际回执确认，避免自动重放未知发送。
- Native 普通 RPC、状态/Raw 订阅和设置副作用只使用现有窗口 instance/generation；连接退休后返回代次错误，不隐式重附着或启动 Host。明确的 `host_attachment` 入口负责建立新连接，旧调用及晚结果继续隔离。
- 物理窗口身份与 WebView 文档 instance 分开。完整页面开始重载时退休旧文档，关闭旧连接及订阅、清理原交付账本和未保存协商登记；同一物理窗口的新文档取得新 instance/generation，HashRouter 页面切换继续复用当前连接。普通 RPC、订阅建立与关闭显式携带调用方 generation，旧文档的排队调用不能借用新代次。账本按文档 instance 归属，晚清理不能删除新文档账本；同一文档显式重连仍保留尚未 ACK 的交付预算。独立 Host 及其已接纳任务不因文档退休而停止。
- 应用外壳仅缓存访问过的已注册页面，数量受路由表限制。工作台的持续接收任务归窗口所有，隐藏时保留订阅和显示缓存，避免恢复读者时从新游标遗漏在途前缀；其他页面以 React Activity 隐藏，保留组件及 DOM 状态并清理副作用。不为切页重新恢复草稿，也不预挂载所有页面。脏工作继续参与未保存协商，隐藏页仍可保存或明确放弃。完整文档重载仍从本地草稿及 Host 状态重建。
- 恢复和回放操作的可信来源由服务解析，与 queued Operation 在同一数据库事务持久化，提交后才发布接纳。来源写入失败整笔拒绝；执行前仍复核当前权限和来源，历史查询仍按当前源权限授权。
- Raw reader、源历史、capture、媒体响应和原生工作都有有界名额及字节预算。慢消费者产生明确 Gap 或停止结果；任务实际结束才归还其持有的预算。
- Raw 已发未确认批次保有其真实内存；准备下一批时遇到该压力先等 ACK。准备批次时同时预留本次编码暂存和 IPC 槽位，入队时移交给输出事件，实际写完后先归还临时预算再通知下一批；重放每次单独取得输出预算，不能在 writer 开始交付后再与源队列竞争内存。准备中的局部分配也持有 reader 的全局配额，直至实际释放。drop_with_gap 同时按逻辑与实际内存压力丢弃未交付前缀或当前事件；每个 reader 在原上限内预留一个合并缺口的空间，不回收已交付帧、不扩大预算，也不把慢读者背压误报为设备故障。
- 窗口的正常订阅终态计入普通交付预算，普通容量耗尽才借唯一应急终态槽，未 ACK 前不释放。授权代次变化结束旧订阅；客户端用新查询重新验权并建立新 reader，恢复查询与订阅共用三次预算，持续拒绝后停止。Raw 接续保留最后已处理游标，历史不足明确报错，旧队列及晚结果不重新投递。
- 普通只读查询在同一连接最多尝试三次以处理授权代次变化，每次重新验权，不重新授权或附着，也不重放 invoke；已接纳操作只重读同一 operationId。Native 内部的设置效果读取与连接设备后的操作/会话读取使用独立白名单，仅重复 `settings.read`、`OperationGet(operation.get)` 和 `session.get`；仅 Host 的 `PERMISSION_DENIED` 回复触发重读，重读使用新 requestId，连接代次变化及其他错误立即返回。平台效果、设备打开和明确授权均在读取循环外；控制通道、媒体和订阅不叠加该预算。状态 reader 使用 SDK 内部查询和自身恢复预算；游标与授权恢复都在快照和订阅完整建立后归零，连续 setup 拒绝仍有界停止。取消等待后仍观察已开始 Promise 的迟拒绝，底层任务保留实际清理责任。
- Rust RPC 在同一物理连接上只合并内容完全相同、仍在途的 `Query` / `OperationGet`，共享原回复且不再写帧；完整信封以有界流式摘要绑定，异参或业务调用同 ID 仍冲突。等待者也计入连接的 256 名额，取消单个已写入查询的等待者不取消其他等待者；写入前责任取消则一并结束等待。清理使用独立身份，旧回复的 guard 不移除同 ID 的新请求。
- Rust SDK 的事件队列限制为 256 帧/4MiB。只有容量不足且新帧为 State delta 时，才移除同一 requestId、订阅及完整游标来源内尚未交付的较旧 delta；新帧保持实际到达顺序与真实 previousCursor，由状态 reader 发现缺口后重新取快照。RPC 回复不经过该事件队列，Raw、终态与其他事件不合并；无法释放足够容量时继续按原边界断开。该策略避免前端暂缓确认使同一状态流积压而连带断开控制请求，不扩大内存预算或伪造连续游标。
- 工作台 Raw reader 在同设备的显式 Native 连接/授权仍进行时，等待其实际结束后再独立验权；不把未完成的授权当成成功，也不重放连接或发送。旧初始拒绝遇到该在途意图时，在原有有界预算内退休并等待；其他设备的意图、真实拒绝及退出隔离保持原边界。
- Native 状态/Raw 早帧只归属仍在建立的订阅 requestId；成功、拒绝或取消后释放其暂存，已退休订阅的晚帧直接丢弃。各建立队列仍限制 256 帧/4MiB；有效建立请求溢出仍关闭相应连接，不以扩大预算掩盖残帧积累。
- 已建立的状态订阅在窗口投递预算暂满时等待前端确认，容量判断与名额预留在同一锁内完成；等待期间不持有窗口或订阅锁，普通 RPC 仍可处理。确认、关闭订阅或 Host 连接失效会结束相应等待；在途写入中断也发布连接失效，不能仅等待对端 EOF。关闭订阅不提前归还已交付预算，只有真实消费确认归还；断开通知也不代替实际连接清理。单帧超限、建立队列溢出和真实通道故障保留原有拒绝边界，见 [Host bridge](../src-tauri/src/host_bridge.rs)。
- Host IPC 按实际成功写入字节区分失效边界。尚无字节的旧事件丢弃、未投递客户端动作以 Failed 结算且不伪造平台回执、敏感回复改为失败；已写部分帧则关闭物理连接，防止新授权沿用旧正文，未确认的平台效果保留 Unknown。写入预算仍为 5 秒。
- 会话 owner 管理唯一持口、发送门控、配置与重连。关闭视图不会伪造设备停止；未完成原生线程继续承担句柄、缓冲区与清理责任。

## 安全与恢复

应用以当前 OS 用户运行，本机隔离不抵御同账户恶意进程。普通 Host 客户端默认只有元数据权限；授权和撤权由明确的本地用户控制入口完成。操作、查询、订阅、派生结果和文件读取都复核当前来源权限。

同一个同步授权阶段共享当前 actor 的文档快照，prepare、持久读取后、bind/dispatch 和最终 writer 各阶段重新读取，不跨异步等待保存快照。期限按实时 Clock 检查，旧 stamp、撤权通知及 writer 交付中的取消边界保持独立。目录可见性计算最多重试三次，在监听登记锁外访问存储；登记时再次复核连接和关停状态，关闭及 shutdown 后的晚结果不能留下监听任务。

文件选择将实际目标登记为受控 ObjectRef，普通前端请求不能通过任意路径扩大权限。固定引用绑定内容 revision，内容变化拒绝沿用。Native 媒体票据绑定窗口与连接代次，每段读取仍由 Host 验权。

并发明确保存可能使媒体解析中的授权快照失效。媒体只在同一 Port/Native generation 对 `PERMISSION_DENIED` 最多额外重新解析三次，每次重新读取和验权，不重新选择文件或授予权限；持续撤权、旧代次及取消仍失败，晚到票据按原生命周期释放。

[recovery.rs](../src-tauri/src/recovery.rs) 处理 ClientState：确认后暂存候选，明确重启时复核格式，将原件归档到 `client-recovery-archive-{token}/` 后安装；失败保留或恢复原件、journal 与错误证据。未来格式在准备和重启阶段都拒绝覆盖，Host 文档损坏或未来格式也阻止写入。

恢复候选是默认 ClientState 文档，会重建其中的窗口偏好、草稿和图库元数据；原 ClientState 随归档保留。它不重置 Host 共享设置或工作区，也不删除图库指向的用户文件，不能用来修复 Host 数据库。

CSP、Tauri capabilities、路径校验、预算和内容校验分别约束对应边界；密钥、输入和日志规则见[安全约束](./conventions.md#安全)。

## 更新与分发

应用版本、协议版本、目录版本和文件格式分别管理。Rust updater 管理检查、下载验签与安装；安装前协商所有窗口及在途工作。更新公钥编译进安装包，deployment 配置仅能更换受控 HTTPS 镜像或禁用更新。

当前发布模板、签名和更新端点尚未启用。组件构建需要同源的桌面、Host、CLI、MCP 和有效收据；后续 Node/runtime 也作为整套发行组件升级，先结算任务再切换，见[构建与发布](./development.md#构建与发布)。

## 关键取舍

- **独立 Host：** 让多个客户端共享唯一设备所有者，录制和长任务独立于窗口；代价是实例管理、身份和整套组件发布的协调。
- **Tauri 桌面：** 复用 Web 界面与系统 WebView，系统能力由 Rust 提交边界控制；浏览器预览与原生验收分别验证。
- **可信 Node 扩展：** 后续统一 SDK、后台和隔离 Web UI；Node 具有 OS 用户权限，代码执行信任与设备 API 授权分别建立，重计算交给受监督 worker。
- **图库与选择分离：** 元数据、共享背景选择和用户原文件各有归属，避免窗口设置副本成为内容权威。
- **安装包固定更新公钥：** 可写部署配置不能替换信任根；换钥需要可信过渡版本或手动安装。
- **线性里程碑交付：** 同一切片的实现、测试、审阅修正和文档集中，经 PR squash 合入；Git 规则见[协作](./conventions.md#协作)。

## 系统串口与 PTY 能力

系统串口由独立 Host 的设备目录提供。目录返回不透明 `deviceId`；打开操作解析当前目录与绑定后，才把受信的系统定位符交给原生提供器。COM 编号、tty 路径和枚举顺序都不是稳定设备身份。目录刷新、stale 与重连规则由设备服务维护，平台提供器只读取 OS 事实。

### 配置与读回

产品保留 5/6/7/8 数据位、五种 parity、三种 stop width 和四种流控。平台不能表达的组合返回 `UNSUPPORTED_CAPABILITY`；驱动修改了请求值时，配置回执保留实际读回，TX 门控保持关闭。打开时只有全部字段确认一致才返回成功。

| 配置              | Windows                           | Linux                                   | macOS                                          |
| ----------------- | --------------------------------- | --------------------------------------- | ---------------------------------------------- |
| 5/6/7/8 数据位    | DCB，随后 GetCommState            | termios2，随后 TCGETS2                  | termios，随后 tcgetattr                        |
| none/even/odd     | 支持编码与独立读回                | 支持编码与独立读回                      | 支持编码与独立读回                             |
| mark/space        | DCB MARKPARITY/SPACEPARITY        | CMSPAR，依驱动读回                      | 通用 termios 无对应表达，明确拒绝              |
| 1.5 stop          | 仅 5 数据位组合；6/7/8 明确拒绝   | 通用接口无法与 two 准确区分，明确拒绝   | 通用接口无对应表达，明确拒绝                   |
| 2 stop + 5 数据位 | 明确拒绝                          | 明确拒绝物理宽度歧义                    | 明确拒绝物理宽度歧义                           |
| RTS/CTS           | CTS 输出门控与 RTS handshake      | CRTSCTS                                 | CRTSCTS                                        |
| DSR/DTR           | DSR 输出门控与 DTR handshake      | 通用 termios 无双向 handshake，明确拒绝 | CDTR_IFLOW 与 CDSR_OFLOW，依驱动读回           |
| XON/XOFF          | 双向软件流控                      | IXON 与 IXOFF                           | IXON 与 IXOFF                                  |
| 任意 baud         | DCB 的 u32 范围，依驱动接受与读回 | termios2/BOTHER 的 u32 范围             | termios 或 IOSSIOSPEED；无法独立读回时拒绝确认 |

读写等待和重连间隔是 Host 策略字段，由 Host 保存；它们不伪装成硬件寄存器读回。数据通路关闭 echo、换行转换、strip、NUL 丢弃和字符替换。RTS/CTS 模式占用 RTS，DSR/DTR 模式占用 DTR；手动改变已被流控占用的线返回 `CONTROL_CONFLICT`。

### 原生资源与排空

每个端口只独占打开一次。专有原生读取线程与单个 TX 或 drain 任务共享同一份受控句柄引用；会话所有者在写入和 drain 待完成期间继续 RX，不允许新的 TX、配置或有副作用控制穿插。写回执分别记录已经确认的接纳前缀、当前在途未知区间和未提交的尾部；取消不会把已提交的字节改写为零副作用。

写入载荷同时保有字节与原分配的预算租约。业务已返回 unknown、源历史已被回收时，未完成的原生任务仍承担这笔预算；实际完成后才释放。Windows overlapped 写入借用这份载荷，不额外复制整块缓冲区。

Windows 使用 FlushFileBuffers，Unix 使用 tcdrain。只有原生调用成功结束才产生 confirmed；驱动队列计数为零、等待一段时间或请求取消都不能生成确认。Windows 通过 CancelSynchronousIo 请求中断 drain；Unix 尝试安装专用 SIGUSR2 空 handler 并定向中断，不覆盖进程已有的该信号处理器。不能安装 handler 或驱动不响应时，等待仍然有界，结果保留 unknown。

取消收尾预算为 100 ms。超过预算后原生线程继续持有句柄、缓冲区和清理责任；会话进入 `ControlUnknown`，同设备保留隔离，晚到成功不自动恢复 TX 或自动重连。活跃与隔离串口合计最多 16 项。会话 close 使用独立关闭信号，在同一 250 ms 总预算内等待实际后端清理及 owner 线程退出并回收 join；`completed` 或 Closed 快照不能单独证明线程已结束，重复 close 与 shutdown 也不绕过此结算。Windows 的最终句柄引用在真实 CloseHandle 成功后释放端口保留并发布清理结果，取消请求或线程先返回不能充当这个证明。

用户显式 `device.open` 可恢复控制线已经 clear 的隔离会话：本进程先等待旧 owner 的真实清理与线程退出，再实际打开和完整配置新会话代次。没有本进程 owner 的持久隔离记录也必须等实际独占打开和配置成功后才替换。失败或清线未确定保持隔离；原 TX unknown 回执和历史不改写、不补发，自动重连不走此恢复路径。超时继续保留 JoinHandle 与责任，业务邮箱满不会丢失关闭，Drop 不等待未完成线程。

桌面发送默认时限由最终字节数、波特率、数据位、校验和停止位计算线路时间，再加至少 1 秒或四分之一线路时间的余量；高级固定模式使用原 writeWaitMs。模式按 Host/设备存于窗口的连接偏好，旧记录默认自动。GUI 仅据此生成本次动作的 writeWaitMs，精确内容验权和真正发送使用相同时限；Host 绝对写入期限及 CLI/MCP 显式参数语义不变。流控停顿仍可超过自动预算，必须如实结算。

领域 write/drain 期限使用 Host 的注入单调时钟；到期通过独立原生取消信号请求收尾，错误仍保留 `WRITE_TIMEOUT`，不会改成用户主动取消。owner 的备用收尾预算是实际时间 150 ms，不依赖领域时钟继续推进。

原生 close 也在持有资源的原生线程执行。实际进程或 OS 锁尚未消失时，停止流程仍需按真实状态报告；线程分离不产生“设备已停止”证明。

Host 关停区分历史发送结果与当前资源责任。TX unknown 回执、会话隔离标记及持久历史保持原样；控制线已经 clear，且会话 Closed、原生清理明确成功并已回收 owner 线程后，历史 TX unknown 不再阻止进程退出。控制线未清除、原生清理失败或线程仍未退出时继续保留责任。界面 close 仍限 250 ms；Host 使用同一关闭信号和完成逻辑，由关停协调器跨 5 秒结算预算持有实际清理等待，不把界面等待超时缓存为永久清理失败。

### 控制与诊断

- Windows 使用 SetupAPI 枚举 present Ports，读取受控 PortName、说明、厂商、硬件标识、拓扑及驱动信息；Linux 读取 sysfs tty 与 USB 祖先属性；macOS 使用 IOKit IOSerialBSDClient 与 USB 注册表属性。
- 序列号缺失不补默认值。Windows 不把任意实例 ID 的末段当序列号；目录还会检查候选唯一性和拓扑变化。
- DTR/RTS、BREAK、purge、队列采样与 CTS/DSR/RI/CD 输入采样通过平台 API。输出调用成功表示驱动接受了请求；物理电平与对端收到 BREAK 需要硬件验证。
- purge 无法对应逻辑流偏移时报告未知丢弃范围，不编造字节偏移。Windows 接收溢出会产生明确错误；Unix 的普通 tty 接口没有统一的溢出计数，持续无损能力需结合实际驱动验证。
- 原生错误保留稳定 code 与 `details.osCode`，不把任意路径或推测的占用进程写入错误文本。

### 验证分层

`cargo test --locked -p serial-workbench-host --lib device::serial` 验证参数编码、读回与可控原生调用的资源生命周期；`--lib device::sessions::mailbox_tests` 验证真实 owner 的 RX、邮箱和有限关闭。

`cargo test --locked -p serial-workbench-host --test serial_backend --test pty_roundtrip` 在目标 OS 运行提供器与 PTY 测试。PTY 对端是独立进程，验证任意分块、字节摘要、RX purge、实际 drain 调用和断连。Windows 上被 cfg 排除的 PTY 用例不计为通过。Linux PTY 的 tcdrain 可能立即返回，因此这一结果不证明成功中断过阻塞 drain。

M6 硬件检查保留 CTS/XOFF 阻塞、实际速率、最后停止位、USB FIFO、输入边沿、线电平与 BREAK 接收。记录 OS、内核、驱动、芯片、接线和时间基准；本机软件用例不替代这些证据。
