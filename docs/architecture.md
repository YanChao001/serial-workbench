# 产品架构

## 运行结构

桌面、CLI 和 MCP 经本机 IPC 连接同一 profile 的独立 Rust Host。Host 统一持有设备、发送仲裁、原始流、录制、操作和共享文档；关闭窗口或客户端后，已接纳任务可以继续。桌面仅管理本地窗口、系统交互和呈现。

资源归属见下表，接口查 [Rust DTO 与生成契约](./contracts/README.md)，系统能力查 [Tauri 门面](../src/lib/tauri.ts)，实证步骤查[专项验收](./acceptance.md)。

Host 进程在实例锁内准备本机 IPC 端点，完成请求处理器和随包组件的启动准备后才公布本次发现记录。发现记录发布后再交付启动 capability 或显式启用的浏览器、HTTP 入口。连接仍须通过现有身份 pin 和握手。

| 位置                         | 职责                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| `crates/core/`               | 公共领域模型、wire DTO、错误、能力目录与导出契约              |
| `crates/ipc/`                | 当前用户本机传输、帧、发现、实例锁和受保护身份存储            |
| `crates/host/`               | 设备、流、TX、任务、录制回放、权限及共享文档服务              |
| `crates/client/`             | Host 的 Rust 认证、连接、启动与 RPC 客户端                    |
| `crates/cli/`、`crates/mcp/` | 命令行和官方 MCP SDK 适配器，共用 Host 能力                   |
| `src-tauri/src/`             | Tauri 桌面组装、Host bridge、窗口、文件选择、媒体、恢复和更新 |
| `packages/contracts/`        | 从 Rust 导出的 TypeScript、schema、默认值及校验器             |
| `packages/host-client/`      | 不依赖 React/Tauri 的客户端投影、reader 和增量解码            |
| `src/features/workbench/`    | 工作台组件、布局、发送草稿及工具                              |
| `src/providers/`、`src/lib/` | Host/设置/未保存工作协调、门面和模型                          |

根 [Cargo.toml](../Cargo.toml) 管理全部 Rust 包和共享 profile，使用唯一的根 Cargo.lock。无头包能够独立构建和测试；`src-tauri/target/` 是配置的共享编译输出位置。

## 客户端入口

- 桌面：`main.tsx`、`App.tsx` 组装 Provider 与 HashRouter；[路由表](../src/routes.tsx)负责布局和导航，菜单、命令面板与快捷键共用 `src/commands/`。手写代码只经 [Tauri 门面](../src/lib/tauri.ts)访问系统能力。浏览器预览使用自己的存储，不是生产 Host 的故障回退。
- 启动：先挂载工作台，窗口草稿读取与 Host 附着并行；设备和历史数据可以稍后就绪。物理窗口、WebView 文档 instance 和 Host epoch 不可互换。切页沿用连接，文档重载退休旧连接；只有明确附着可建立新代次，普通 RPC 不隐式启动 Host。
- IPC：原生桥只投递一次。失败发生在部分写入后须断开物理连接；不得重发可能已经产生副作用的请求。普通本机客户端和配对浏览器的状态投影按 scope 的实际读授权绑定规则代次，新增其他目标的权限不会中止该订阅。LAN 投影仍服从远端共享与会话绑定。验收覆盖新会话授权与状态投递并行、实际撤权和会话换代。失去授权后只能按当前权限重读或重订阅，不能补授权、重放发送或恢复旧 reader。
- CLI/MCP：Rust 客户端认证到同一 Host，使用当前授权的目录。MCP 在同一连接上完成分页发现和执行；目录版本或可见性变化应重新发现，而非重试业务。见[目录适配](../crates/mcp/src/catalog.rs)与[调用示例](./development.md#hostcli-与-mcp)。

本机握手与 `host.attach` 共用 [Host 版本契约](./contracts/README.md)，身份挑战绑定所选协议。IPC、HTTP、配对 WebSocket 和 LAN TCP 各自认证并返回同源升级目标。桌面、Host、CLI 和 MCP 整套升级，浏览器刷新 Host 页面，LAN 两端分别升级。配置、录制、凭据及操作记录各自版本化。验收覆盖拒绝旧版、正常附着、同 profile 升级及恢复。

跨入口比较时，固定资源 Host、目标、代次和当前有效授权。业务查询返回相同的可见内容，动作遵循同一接纳、取消、去重和结果读取规则。选择文件、访问剪贴板等系统交互由具备相应能力的客户端执行，无可用客户端时报告不可执行。来源密钥和代码执行信任的变更还须验证本地用户控制身份。普通身份的目录隐藏这些动作，已知动作 ID 也须拒绝越权调用。见[本地 IPC 与用户控制](./contracts/host-v0.md#本地-ipc-与用户控制)。

发送历史的固定项使用 ClientState 的窗口存档，只保存工作区、Host 和操作 ID。桌面关闭后重开沿用同一窗口记录，配对浏览器在同一标签页重载时沿用现有会话存档。每窗口最多 64 项。保存按 revision 合并单个明确的固定或取消固定操作。已固定项的来源授权与留存情况仍由当前 Host 验证，历史原始字节保留在 Host。

快捷键速查和自定义键位共用当前窗口的命令注册表。自定义键位随该窗口的客户端偏好保存并沿用存档修订检查，空字典保留默认绑定。F1 打开速查，Escape 关闭弹层，发送编辑区继续单独处理发送键。可用操作的键位冲突在保存前提示，分派时保留冲突操作的菜单入口。

### 配对浏览器

由独立 Rust Host 显式启用本机浏览器入口，监听 loopback 并用实际地址校验 Host 和 Origin。由本地用户控制入口完成首次配对，浏览器以普通身份附着，业务能力沿用 Host 的授权、目录和撤权。配对凭据和附着凭据按各自生命周期回收，URL 和日志仅记录地址与稳定错误信息。关联约束见[本地 IPC 与用户控制](./contracts/host-v0.md#本地-ipc-与用户控制)。

Host 为每个 profile 分配一个普通浏览器身份，私有凭据存入 OS 保护的 profile 文件，页面仅得到用于握手的客户端 ID。受保护的本机继承管道为测试启动器传递一次性配对码。首次握手前，浏览器随机生成 32 字节作为独立重连凭据，以无填充 Base64URL 编码与配对码一并提交。Host 接受配对时消耗配对码，只在本次监听实例保存重连凭据的校验值。浏览器已持有自己的重连凭据，首次回包丢失时仍可使用它恢复连接。桌面本机身份的权限与凭据保持在本机 IPC。

浏览器复用同源构建的工作台、HashRouter、控制层和状态投影。Host 在受控位置读取随安装包提供的页面资源，运行中用入口标记选择浏览器传输。共享设置、工作区和会话由 Host 确认，草稿、导航和跟随状态各归客户端。窗口、文件等本机系统能力按客户端实际支持情况接线。

浏览器握手后复用 Rust 的请求校验、授权复核和断开清理。Control 与 Raw 分别管理流量及生命周期。静态 HTTP 与 WebSocket 共用连接预算，关停回收两类套接字后再释放 profile 实例锁。恢复状态用查询和订阅，已接纳的操作按原请求读取终态。

配对浏览器使用普通身份打开来源仍受信的签名终端或签名图表。工作台按操作回执分段验证入口和资源，单独的静态帧使用限制路径的 CSP 和 opaque origin，在帧内为已验证的预构建脚本与样式创建临时资源。配对与 Host 凭据留在工作台。包端口只能确认当前 Raw 批次或派生页，视图单独附着 Control 和 Raw，关闭时释放自己的连接和 reader。图表沿用当前激活的独立采样操作，按操作、Host 实例与会话代次核对派生页。关页期间采样继续，重开的视图读取仍留存的样本。源权限、插件登记代次和会话代次在交付前重查，撤权、导航和主连接结束后回收帧、端口和读取者。 [配对浏览器验收](./acceptance.md#配对浏览器)

AI 活动按目录声明的页面、面板和 Host 解析出的会话代次定位。跟随复用工作台已有面板及焦点回退。编辑输入框或操作面板时保留当前位置，重复查询和晚到结果沿用首次活动。 [配对浏览器验收](./acceptance.md#配对浏览器)

桌面通过已认证的本机用户控制连接管理当前实例的浏览器入口。桌面仅提供随应用构建的工作台目录。Host 安排配对和撤销的顺序，按用户选择给专属浏览器身份授予只读或工作台操作权限。撤销停止该监听、回收读取者并退休浏览器授权，串口会话继续由原 Host 管理。重新配对使用新地址与新配对码。验收核对普通客户端不能管理入口、撤销确认后旧浏览器连接已退出、原桌面仍在同一会话收发。

桌面在「活动」面板发起人工接管时，以当前窗口的本机用户控制连接提交同一个 `session.takeover`，绑定所选 MCP 身份和当前串口代次。业务连接继续用于查看同一操作的终态。缓存的活动和客户端附着类型只用于选择，撤权仍由 Host 验证本机用户权限并结算已接纳的写入。配对浏览器保持普通身份，涉及撤权的接管须由本机用户确认。验收对照所选 AI 和另一身份的写入、接管回执以及原会话的连续性。

浏览器有目标串口操作权限时，可以向当前 Host 提请接管。Host 同时保留一项待确认请求，绑定配对连接、所选 MCP 客户端和串口代次。桌面通过活动投影收件，本机用户确认时只提交请求标识。Host 用保存的目标调用已有 `session.takeover`，浏览器收到同一操作的接纳回执后等待终态。确认前关闭浏览器、撤销配对或请求过期都会撤回待确认状态。验收包含拒绝、过期或连接结束后的晚确认，以及确认后所选身份与另一身份的真实串口写入。

#### 配对浏览器文件交接设计（IO-18）

配对浏览器从用户显式选择的文件读取字节。继续沿用已认证的 Control 连接，托管文件仅用于当前 Host 的文件传输。本机路径登记依赖本机用户控制权限。另开上传 HTTP 入口需要独立的凭据、来源校验和撤销机制。复用 Control 保留既有的配对、同源检查、连接预算和断开清理。

开始交接时核对连接的操作权限、目标会话和代次，并校验文件长度与预留空间。Host 用已锁定的 `tempfile 3.27.0` 在 profile 私有目录创建无公开路径的临时文件。Unix 取消目录链接，Windows 依赖关闭句柄删除，进程退出由操作系统回收。该 Rust 库从现有测试依赖移入 Host 运行依赖，许可为 MIT 或 Apache-2.0，构建无专用脚本，发行增加 Host 静态链接代码。用户文件名留在客户端用于显示，日志记录稳定错误和进度计数。浏览器逐块读取，Host 按预期偏移写入、累计长度和计算摘要。客户端等待当前分块回执后再读下一块。交接限制沿用文件传输的最大源文件，临时数据受按连接和 profile 的配额约束。越界、分块错序、写盘失败及取消均回收预留空间。

封存回执返回接收进度和摘要。确认提交携带上传标识及完整的 `transfer.file` 调用。引用只绑定当前 Host、上传标识及固定版本，目标、会话代次、范围和原始写入授权在接纳时复核。重复提交先查同一请求的持久回执，新请求才尝试接管封存文件。主动丢弃、断开、停止配对或撤权先于持久接纳时释放临时资源。接纳在 SQLite 提交点复核连接和监听器，两者只在实际提交期间与关闭操作串行化。等待 Store 排队期间连接仍能关闭。操作接纳后由现有传输任务持有文件句柄，范围、速率、停止、设备写入和回执沿用 `transfer.file`。接纳后的写入仍受任务授权检查。临时文件在传输执行结束后随句柄关闭回收，回执仅按目标会话授权读取。回归覆盖同源只读配对、第二客户端、断开重连、同一请求号回执查询、过期会话、文件大小上限和写盘失败。界面按[文件拖放发送](./acceptance.md#文件拖放发送io-18)复验。

### 复现实验包（SESS-09）

实验包是可移交的版本化 JSON。工作区只复制布局、视图行为、线路参数、设备类型和 VID/PID。绑定和视图使用包内序号，导入后需要重新绑定目标设备，重连关闭。工作区名称、原绑定的主机与端口标识、USB 序列号、物理路径、命令正文、操作输入和错误详情不进入包。解析器记录 Host 已安装的包 ID、版本和归档摘要。录制保留有权读取的稳定引用及摘要。操作结果保留所选已结算操作的动作、终态和时间。固件版本由实验者显式填入，导入时标为待核对。

两个 Host 查询在工作区目标上提供导出和只读检查。导出可指定工作区修订，并沿用现有工作区、包、录制和操作的授权。检查仅按照同一包身份、摘要、当前权限和启用信任状态核对依赖。来自其他 Host 的录制保留原引用并提示重新关联。检查不会建立文件访问权、安装解析器或打开端口。导入确认使用原有工作区预览和修订保存，附件与敏感正文需要各自的授权流程。大包、未来版本、未知字段和无效引用在检查前拒绝。运维诊断继续使用独立入口。

解析器选择、导出和依赖检查共用 Host 安装快照中签名清单的 `contributes.parsers` 声明。插件管理仍读取完整目录。解析器目录保留已禁用的历史版本供导出，导入时按启用和执行信任状态提示可用性。分页先应用筛选，再按同一个修订和游标读取，浏览器无需读取整份包清单。验收用有解析贡献的分帧包和无解析贡献的自动化包验证这条边界。

### 本机 HTTP 控制

外部程序可用本机 HTTP 连接同一 Rust Host。Host 仅在启动器显式请求时监听 IPv4 loopback，并通过受保护的继承管道交付地址和本轮 Bearer 凭据。凭据传递入口在初始化 profile 或监听前验证管道，实际写入前再次验证。每个 profile 为 HTTP 分配普通身份，具体数据读取和设备操作继续由本地用户按目标授权。HTTP、配对 WebSocket、LAN TCP 各自验证凭据和连接来源。

HTTP 把有界的单次请求交给现有 Host 校验和业务服务，复用目录、接纳限额以及发送答复前的授权复核。客户端按页读取原始数据并独立查询操作终态。断开 HTTP 请求停止等待，已持久接纳的操作由 Host 继续结算。关停时 Host 停止接纳并回收 HTTP 连接，随后释放实例锁。验收比较 HTTP 与本机 IPC 的目录权限、操作回执、游标和原始事件来源，并覆盖撤权后的读取和写入。 [HTTP 契约](./contracts/host-v0.md#本机-http-控制)

## LAN Host 连接

LAN TCP 入口由端口所有者 B 显式启用。Host 在受保护的 profile 中保存专用 Ed25519 密钥。两个 Host 经管理员确认对端的公开密钥指纹，再用 TLS 1.3 的原始公钥认证彼此。指纹按 DER 编码的 SubjectPublicKeyInfo 计算 SHA-256，地址和发现结果只用于定位。连接必须协商本项目的 LAN 协议版本，每次重连重新校验两端公钥，禁用会话恢复和早期数据。使用现有锁定的 Rustls、Tokio 适配器与 ring 实现加密和签名校验。此传输适用于受支持的 Windows、Linux 和 macOS 开发目标，新增直接依赖沿用现有锁文件版本及许可。包体影响在发行候选测量。

TLS 完成后，双方在加密通道中交换 Host ID 和当前实例代次。接收方核对发起方的 ID 与受信公钥，再返回自己的身份。发起方收到确认并核对对端 ID 后才能使用连接。共享层据此授予共享范围、校验委托及管理租约。启停共享或撤销配对时，B 停止接纳对应连接并回收它们，按租约和接纳状态结算串口工作。传输验证用真实 IPv4/IPv6 套接字检查双向认证、未知密钥拒绝、协议不匹配和重启身份。Host 实例测试核对同一密钥下的错误 Host ID 拒绝及重启后的实例代次。跨机角色互换和真实设备按阶段验收。

B 的本地用户控制身份批准配对和每个共享目标的读取或操作权限。已批准的公钥绑定和精确授权规则在同一次 Host 授权事务提交，共用现有的授权代次和撤权检查。LAN 身份通过当前配对取得，普通本地 IPC 凭据不能附着该身份。服务端确认握手前重读配对，撤销配对使仍在握手的旧配置拒绝接纳。另行授予设备和会话权限，实际数据按 B 的目标及会话代次核对。

已认证连接显式开启 Control 或 Raw 通道，再使用与本地 IPC 一致的帧和请求处理。Raw 附着使用同一配对身份的活动 Control 凭据，LAN、配对浏览器和本地 IPC 分别管理附着凭据。本机管理指令由本地控制连接接入。配对撤销关闭对应通道，请求接纳、流授权和操作结果仍由 B 的现有服务判断。网络连接有独立名额，端口所有者显式启用监听。

监听和配对经本地用户控制通道管理。绑定成功后再替换监听，停用时关闭新连接入口并通知旧通道退出，已接纳操作按原规则结算。配对和授权保留在 Host profile 中。监听地址由用户当次选择，Host 正常启动时保持关闭。链路本地 IPv6 的本机监听与连接均填写当前机器使用的数字接口索引。作为发起端填写到达该链路的本地接口索引，配对仍按 Host ID 与公钥指纹判定。停用、恢复监听后重新认证。继续读取使用核对过的 Host、会话代次和游标，新的写入仍须明确发起并取得自己的回执。端口共享变化更新接纳配置，已附着连接继续按当前授权检查请求。

A 在 TLS 和对端确认之后，使用 Rust 客户端的正常附着、请求分发及 Raw 读取。配对身份可以查询状态目录，B 对每项投影校验精确授权。Control 与 Raw 都核对 B 的实例代次。重连建立新通道，核对 A 的配对身份及 B 分配的 actor，重新配对后的身份须显式建立连接。已接纳的请求可用原编号查询或由调用者显式重试，网络客户端不会自行重发。

应用路由从 A 已认证的普通客户端取得身份，并通过配对连接转发。B 以当前配对和来源客户端生成稳定的独立 actor，操作去重与输出归属使用该 actor，授权始终读取 B 当前配对的共享规则。两条通道必须绑定同一转发身份。A 不转发本地凭据、任务委托或用户控制权，B 用来源名称标记 MCP 活动。相较于整台 A 共用一个 actor，这让 B 能独立识别每个发起者，并在配对有效时跨重连查询原操作。验收覆盖不同来源使用相同请求编号、Control 与 Raw 匹配、按原 actor 查询结果，以及撤销配对收回全部转发通道。

A 的本机 IPC 先完成本机身份认证，再为获准使用该对端的客户端建立路由。A 的管理员按客户端授予 `lan.connect`，B 决定实际能读写的串口范围。A 持有配对私钥并中继现有帧，客户端使用 B 返回的附着身份和实例代次，Control 与 Raw 保持同一条路由。相较于客户端直接持有配对私钥，A 可以撤销本机客户端的访问并关闭在途连接。验收用正常客户端程序确认授权前后的行为、B 的真实结果和撤权后 B 本地会话的连续性。

B 在配对授权文档中登记已经附着的 LAN 客户端。人工接管沿用本地 `session.takeover`，按选中的 actor 与精确会话代次收回 `device.modify`，等待已接纳任务结算。限制存于配对之下，重连继续生效。B 的用户控制身份可用 `auth.authorize` 在共享操作权限内重新授予该客户端写权。接管和重新授权推进该客户端在这次会话上的写权限版本，旧接纳不能沿用新许可，读取及同一对端其他客户端的权限继续按各自规则执行。

设备级共享沿用 B 建立会话时登记的设备归属和当前会话代次。A 由设备授权打开串口后，按同一共享范围发现会话、读取数据及操作。明确设置的会话共享优先。同一客户端在该会话上的接管限制仍生效。A 的 Control 和 Raw 通道绑定接纳时的 `lan.connect` 规则。授权变化时暂停转发并复核，同一规则撤销后旧通道退出。重新授权允许新建通道，B 按原规则结算已经接纳的操作。

桌面的路由归当前窗口文档。本机连接和选中的远端连接各有独立代次、订阅和交付预算。切换远端保留本机连接，设置、工作区和本地资源可使用原主机身份。串口业务使用 B 分配的普通身份，远端连接上的本机特权操作受限。切换失败保留当前连接，同一文档重连继续核对所选对端和转发身份。返回本机回收远端连接，关闭窗口或重载文档同时回收两条连接。验收对照两份真实 Host 的设置读取、串口收发、远端代次失效和会话连续性。

桌面显式连接时，本机用户控制通道仅为当前桌面身份授予已配对 Host 的路由权限。配对身份确认及普通业务授权仍由两端 Host 执行。工作台用远端会话、设备与 Raw 投影打开共享视图，本机设置和工作区文档使用 A 的连接。最近连接地址是客户端输入提示，信任始终在 Host 配置中。

LAN 的设备列表由 B 按当前共享权限筛选。明确共享设备时显示该设备。仅共享会话时，列表只补充定位该会话所需的设备名称与传输能力；硬件身份细节保留给设备授权。当前未共享的设备不进入列表。B 的本地连接仍使用完整设备目录，A 的桌面不发起 B 的硬件枚举。

B 按精确串口会话代次发布命名 MCP 的活动摘要。会话投影与对应活动投影绑定相同的 `metadata.read` 授权，撤销共享结束活动订阅。新代次从空活动开始。A 从已授权的会话投影合并活动，用既有跟随控件定位当前串口和面板，重复观察更新原记录。B 的本机活动和浏览器接管请求仍由 `host.activity` 提供。

预定义命令由 Host 在 SQLite 中按工作区保存。组和命令的目录页只读取摘要，选中条目时单独取得正文和发送参数。命令库 revision 与工作区模板独立。翻页要求同一 revision，跨页改序以目标组和稳定命令 ID 定位，排序与租约无关。写入、排序、revision 和操作结果证据在同一事务完成。复用工作区归档保护，增量表保持原数据库格式版本和已有文档数据。桌面用户打开命令库时，原生入口仅在必要时授予当前工作区内容读取权限，随后的翻页和条目详情走普通业务请求。修改沿用显式文档意图，通过当前连接代次核对目标及终态回执。配对浏览器仍使用其现有授权。工作区切换会取消界面等待，已接纳的写入由所属 Host 继续结算。

命令库归档采用有版本头、逐条 JSON 记录及尾部条数的 UTF-8 文件。导出按同一命令库 revision 读页，写入同目录临时文件，发布前复核 revision、文件身份及授权。导入先用独立 SQLite 暂存库校验记录、重复 ID、分组引用和完整尾部。既有分组和命令保持原值，冲突 ID 分配给导入副本，命令按归档顺序追加到各自导入分组。最终提交用预期 revision 和当前工作区归档状态校验，新增内容和结果证据同事务提交。单条记录受字节预算约束，归档条数随可用存储扩展。

已保存命令由发送区按需展开为窗口草稿。正文、发送格式、编码和行尾覆盖一起进入草稿，连接串口时继承到认领该草稿的视图。临时参数随草稿的归属维护，既有草稿文件仍保存正文。命令模板及其参数持久化在 Host，临时变量值仅进入展开后的正文。发送使用普通预览和会话授权，由用户另行触发。

共享设置与工作区使用 revision CAS。保存只确认相应提交，冲突重读且保留草稿；窗口的日常标签调整不立即写入共享模板，显式保存才更新模板，其他窗口的运行布局独立。

工作区已保存的视图、连接预设不等于窗口当前草稿或实际打开的设备。加载工作区不连接、不发送；优先关联已确认的设备身份和 session epoch，匹配歧义时显式选择。已确认快照与后续输入分开。草稿按窗口、工作区和视图区分，切页不重复恢复；未保存工作统一参与离开/退出协商。日常操作见[工作区操作](./development.md#工作区操作)。

字符重映射（LINE-10）先提供方向独立的文本预览。RX 使用经授权的当前视图留存样本，从连续原字节按接收编码解码。TX 使用当前文本草稿，预览发生在编码及附加行尾、校验之前。HEX 草稿可用示例预览，二进制传输不进入字符处理。规则按输入的 CR、LF、CRLF 边界处理换行，在同一输入行内解释 BS，再对单个 Unicode 标量作一次替换和大小写转换。替换结果不会再次匹配规则。草稿保留在当前工具窗，原始内容和映射内容分别以转义文本呈现。

发送接线将预览和实际写入共用同一规则快照，随后按现有编码、尾缀与校验生成最终 TX。通过 Host 已有的操作输入访问边界保留原稿和规则来源，记录变换版本及配置摘要，并核对归属、大小上限和权限。RX 接线按同一来源的连续解码文本应用规则，遇配置、来源、报文或缺口边界停止跨段解释。Raw、HEX、包校验及原始录制沿用原字节，字节定位以原始范围为准。

应用 RX 规则只建立窗口内的接收投影，作用域含当前视图、Host 实例、订阅代次和会话代次。切换视图、失去流或换代结束应用，草稿和已应用规则各自有明确状态。投影沿用接收区既有冻结与跟随，按 Raw 字节范围展示结果，支持切回原始 HEX 定位。每轮只解码最近 256 个原始事件中的至多 64 KiB 文本来源，展示文字受独立上限约束。截去旧范围时在接收区标明。UTF-16 裁剪首部按连续接收段或报文来源对齐，保留裁剪后的实际范围。映射模式的自动编码选择器与正文共用最后一段可用文本的检测结果。按源、串口配置、源时钟、分片标识与字节连续性分段。源缺口、报文终点与配置边界结束解码，显式二进制消息不参与字符映射。接收统计、保存、协议解析和录制直接使用已有未映射 Raw。

字符重映射属于基座。桌面与配对浏览器共用工作台的 TypeScript 映射，预览与发送共用规则和计算，实时接收继续按现有 Raw 读取边界。映射发送是当前工作区视图和会话代次的文本发送状态。映射、编码、行尾和校验从显式发送时的同一界面快照计算，HEX 按自身输入提交。发送请求复用 Host 的 `session.tx` 接纳事务保存有界原稿和版本化规则。原稿经已有 `operation.input` 权限读取，发送环和录制沿用最终字节及实际结算。这样一次请求只有一个接纳与恢复边界，原稿的保留期也随原操作。

发送前预处理（IO-15）从发送编辑器显式生成字节预览。顺序为字符映射、正文编码、预处理步骤、行尾和校验。通用步骤用随工作台分发的 TypeScript，复用字符编码和最终 TX 字节上限。步骤按顺序完成，编码错误、无效定义、空结果或超过预算时停止整次预览。发送读取完整的最终快照，沿用 `session.tx`、预期会话修订和实际写入回执。

扩展步骤调用当前目录中显式选定的会话查询。通过配置把输入和结果的 Base64 字段映射到该查询既有的参数与输出，使用固定 Node、公开 SDK 和现有授权。查询没有动作任务上下文，预处理只接受它返回的有界字节。应用分别绑定窗口视图、草稿、步骤定义和连接会话。变更或关闭时结束旧等待，晚结果不能更新当前预览。启用后待预览、失败和过期均不向单次发送、按住连发或全局热键提供字节。M5 通过宿主市场接入（FUT-07）安装专用加密与压缩扩展，在同一入口验证。 [界面草稿](./ui-design.md#发送前预处理草稿io-15)

工作台按住连发沿用单次发送接线。手势绑定当前窗口视图、Host、会话代次、会话修订及已计算的最终字节。每笔携带预期修订，由 Host 重新校验写权限和队列。核对操作身份、字节和完整接纳范围后才安排下一笔，未知、部分接纳或失败时结束调度。释放手势、目标或草稿变更时停止后续提交及本地等待，已提交操作继续由 Host 记录结算。按住状态仅在当前前台视图有效。

全局发送热键归桌面窗口。绑定由该窗口显式注册并在销毁或重载时释放，关闭后隐藏到托盘的窗口暂停触发。操作系统只提供按键事件，前端以当前可写视图的标识丢弃晚事件，然后复用单次发送和回执。会话、修订、草稿和授权在提交时沿用正常的 Host 验证。绑定冲突时保留原注册。插件和配对浏览器无法设置系统级绑定。Linux X11 沿用原生注册，Wayland 会话须由系统 GlobalShortcuts portal 同意和绑定，验收按桌面会话分别留证。

离开工作台路由时撤回桌面热键的发送目标。缓存页面继续接收，返回工作台后以新修订发布当前发送目标，晚到的旧热键事件随之丢弃。

Wayland 用首选组合请求初次绑定，由系统决定实际键位。活动会话的新键位从系统设置管理。应用支持通过 portal v2 的 `ConfigureShortcuts` 打开设置，较早的门户在编辑区引导用户到桌面设置。请求设置由持有绑定的窗口发起，系统事件是键位变化的依据。改变键位时暂停该注册的发送授权，当前视图重新发布授权后再接纳触发。 [门户协议](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html)

KDE 应用改键时先移除旧键，再分配新键。同一门户会话报告无键位时立即停止派发并显示关闭，会话继续接收系统变更。系统重新分配键位后，仍须由当前文档重新提交发送目标。用户从关闭状态发起新申请时，先回收原先无键位的会话，再等待系统确认。验证覆盖移除与分配之间的旧事件、重新授权和再次申请。 [KDE 应用快捷键变更](https://github.com/KDE/plasma-desktop/blob/v6.6.7/kcms/keys/globalaccelmodel.cpp#L202)

Wayland 的请求和系统绑定归窗口当前文档及独立的会话总线连接。文档换代立即撤回派发资格，并由原连接依次显式关闭待定请求和系统会话。关闭调用各有期限，调用失败或超时后仍断开原连接回收本地资源。清理待定申请期间保留原申请的占用，避免新文档与旧系统弹窗争用键位。门户撤回或退出同样终止派发。验收从独立桌面核对待定弹窗关闭、旧键停止写入，以及新文档可以显式申请。两种 Linux 后端沿用同一当前草稿和授权检查。 [请求关闭](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Request.html#method-close) · [会话关闭](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Session.html#method-close)

接收编码以当前视图中最近连续 RX 段的有界前缀识别。BOM、严格 UTF-8 校验和统计候选保留各自的依据，统计分数用于排序。菜单在手动编码下也可按需分析。选择候选只更新当前视图的解释，文本、ANSI、搜索与文本导出从同一原始留存重新解码，HEX、录制内容和发送编码保持原有归属。验收核对拆包、证据不足、候选切换后的字节一致及保存范围。

HEX 视图只重排当前留存的原始字节。地址采用来源的无符号 64 位偏移，ASCII 栏以点号显示控制字符与不可打印字节。格式变更按流来源、事件和原字节端点恢复选区，数据被淘汰时放弃已失效的选区。分组、换行和附加列共用文本块，数据大小不转化为逐字节 DOM 数量。验收核对超过安全整数的地址、末行对齐、跨行与 ASCII 选区。

发送区复用原生多行文本框承载键盘、选区和输入法，行号与着色随文本框滚动。缩进和注释作为一次替换交给输入框撤销历史。混合草稿的块注释仅在引号外解析，注释上下文通过显式 HEX 预览应用。普通文本和 HEX 草稿沿用既有字节规则，发送仍使用统一的字节快照。

文本高亮是工作台窗口的显示偏好，实时文本、回放文本和已展开的长记录文本页共用规则。规则按顺序匹配显示文本，靠前的规则优先覆盖重叠字符。把文本分批交给可终止的 Worker，预算限制批次大小、单行高亮数与执行时间。新数据优先，并在文本和规则完全匹配时复用结果。修改规则、中止视图时取消旧任务。错误规则和超时给出反馈，采集、原字节和回放位置保持独立。

静默分帧属于每个客户端的当前会话读取器。连续原字节按收块源单调时间分组，默认间隔 100 ms。超过阈值、时间倒退、来源或时钟粒度变化、配置变化、缺口及其他显示事件都会结束当前分组。阈值切换只关闭当前分组，后续接收使用新值，现有分组和采集游标保留。包时间使用最后一个收块的时间戳，包长度按当前留存的原字节计算。标明时间来源和分辨率，Host 收块时间无法测量 USB 合块内部的线路间隔。

长记录折叠只改显示投影。来自同一 Host 实例、会话、配置和时钟的连续消息片段共用一个摘要。已声明的消息长度超过 64 KiB 时立即显示摘要，普通显示记录超过同一长度时也折叠。摘要保留实际留存长度、声明长度、消息类型、缺片状态和发送错误。展开后从当前留存的原字节逐页生成文本或 HEX，单页最多 64 KiB，文本解码跨页接续。普通行的增量解码仍延续连续字节。大型回放条目沿用原有引用和显式读取。

接收记录编号使用显示投影的三个独立坐标。行号按当前留存快照的未过滤显示行编号，显示包号沿用接收留存的逻辑记录分组，每个原事件保留 Host 实例、会话代次、完整事件序号和分段的字节起点。复制的定位号按原事件恢复，允许同一个显示包内的多事件和发送意图被回执替换。跳转冻结当前显示快照并撤销显示筛选，避免持续接收推动目标位置。已经离开留存范围的定位号显示不可用，多来源的重复事件号要求使用完整定位号。

接收视图的方向和匹配过滤作用在当前显示快照。RX 和 TX 各自按配置、会话连续性及自己的文本编码在可取消的工作线程搜索，收发之间不拼成同一命中。端点保留原事件索引，跨记录命中覆盖相关的完整显示行。仅完整结果参与显示或隐藏，查询出错或预算耗尽时保留可见数据。缺口和控制记录继续显示。统计按可见记录计算，录制、原始订阅和 Host 操作保持原有边界。

多格式复制显式锁定同一个 HEX 或 ASCII 原字节选区，单次上限为 64 KiB。二进制表示直接使用快照。文本按当前方向的编码解码，操作前可切换。带时间戳的输出按现有来源事件分段，保留方向和原始字节偏移，优先使用来源时间或显式选择接收时间。连续解码器处理跨事件字符，JSON 字符串转义记录正文。输出经共用剪贴板入口实际写入，界面按写入结果反馈。

数值解释从 HEX 或 ASCII 选区锁定当前同一来源与方向的连续原字节。一次最多复制 8 字节供显示，跨缺口、配置修订或不同来源的选区会被拒绝。按所选位宽和字节序从选区起点解释同一序列，十进制整数采用精确位宽，浮点保留负零、无穷和 NaN。解释面板只读取工作台已有数据，录制与会话状态保持由原有入口管理。

工作台的 ANSI 终端默认只读。它按当前接收编码、会话代次、配置修订和连续字节范围解释最近的 RX 段。缺口、来源变化或前缀淘汰会销毁旧渲染器，重新解释仍留存的连续段。渲染器同一时间仅排队一批，关闭视图即释放。日志、搜索、录制和设备权限沿用原始流。窗口行列仅决定本地版面。

SEC-08 将 ANSI 的显示和宿主动作分别授权。实时接收可呈现 OSC 8 的 HTTP(S) 链接，必须由用户主动激活并通过现有宿主外链策略。录制尾部与回放消耗 OSC 8 控制指令，保留其标签和样式，按普通文字显示。改变来源或链接许可时重建 ANSI 渲染器与链接索引。所有来源的 OSC 52 都由渲染器终止，终端序列没有原生剪贴板、下载、文件选择或保存入口。显式复制和保存从用户当前的选择或渲染画面生成内容。原始 RX 与录制字节继续走已有读取权限。

ANSI 回滚上限属于显示窗口的本地偏好，默认 3000 行，可在 0 至 50000 行内调整，历史文件缺项按默认读取。改限额时，用当前可见来源的留存字节重建渲染器。回滚面板按 xterm 当前保留的渲染行显示视口位置，可跳首行、尾部或指定行。xterm 原始行标记被裁剪或清除后显示早期行不可用；Raw 留存淘汰沿用接收层的独立提示。备用屏幕只显示其当前有效行。复用接收冻结快照，采集和磁盘录制继续由 Host 运行。验收覆盖保存恢复、大量行、裁剪、跳转、备用屏幕和冻结期间的接收。

ANSI 屏幕搜索以活动缓冲区的显示内容为范围，连接软折行，保留硬换行边界。控制序列和已覆盖的字符仍从原始字节搜索查找。正则交给可取消、限时的工作线程，匹配位置以显示单元格投影，覆盖宽字和组合字符。接收改写、重排、备用屏幕切换和视图重建时撤销旧结果，持续接收时可冻结视图进行检索。验收对照显示高亮、跳转顺序、原始字节作用域及晚返回的取消。

ANSI 的基本 16 色随浅深主题映射，扩展索引色由 xterm 的标准色表处理，设备给出的 24 位颜色按值显示。彩色快照读取当前可见行的渲染颜色，把文本和前景、背景写成 ANSI 文本，通过原生保存对话框或浏览器下载。输出只生成 SGR 样式与换行，设备控制字符和链接目标不进入快照。原始录制继续保留收到的字节。验收用相同色样对照主题切换、屏幕与导出。

ANSI 与文本和 HEX 共用终端字体偏好。开启编程连字时，用固定版 xterm 的字符合并接口将同一属性段内的连续运算符交给浏览器字体塑形，字体无对应字形时仍显示原字符。单元格边界继续由 xterm 管理。光标落入连字范围或选择覆盖其中一部分时，渲染器按原单元格显示。浏览器和桌面共用这一入口。

对端约定采用 CSI 时，已启用 ANSI 输入的可写会话可以单独授权上报本地行列。尺寸取自本地布局，稳定后通过同一发送队列提交 `CSI 8 ; rows ; cols t`。连续变更只保留最新待发尺寸，Host 的已接纳回执继续按原发送规则观察。撤销授权、冻结或离开会话会清除待发尺寸。设备输入的窗口命令无法替代本地布局或 PTY 的原生尺寸协商。

POSIX shell 对端可以手动接收终端环境变量。ANSI 的会话设置允许选择 TERM 和颜色能力，尺寸默认读取本地布局，也可明确填写。按照用户选定的值生成有限字符集的 `export TERM=… COLORTERM=… LINES=… COLUMNS=…`，经同一个已授权发送队列插入。操作者在终端按回车执行。该设置与会话代次绑定，普通串口流在用户操作前保持静默。

用户可为当前可写会话启用键盘发送。事件必须来自获得焦点的终端键盘，已启用的应用快捷键、复制选区和 Shift+Tab 继续交给原焦点与快捷键系统。字符按发送编码转换，VT 转义与控制键保留原字节。设备自动应答留在渲染器。本地键盘输入按小时间窗合批，最多保留 4 KiB 待发送数据，同时等待一项真实操作结算。部分发送、未知结果、溢出或换代会停止继续投递。关闭视图与撤权会丢弃未提交的字节并停止等待，已接纳操作仍由 Host 结算。

本地键入回显由当前已授权的 ANSI 键盘会话显式开启。它在独立区域显示已进入本地队列的可打印输入，支持基本退格和换行，最多保留 4,096 个 UTF-16 代码单元。设备 RX、彩色屏幕导出及原始录制仍取各自的来源。停止键盘输入、权限换代、冻结或关闭视图会清空本地文本。发出、失败或未知结果继续由原有活动回执报告。

终端粘贴经用户确认后提交单个 `transfer.paste`。Host 对当前会话代次校验设备修改权限，并按粘贴字节总量预留队列容量。粘贴的有界不可变字节与固定文件共用独占发送、分片间隔、速率和逐块持久回执，回执读权限取自原会话。取消提交给 Host 结算，已确认和未知区间按实际写入保留。验收比较分片顺序与间隔、并行普通发送的位置、取消后的终态和已确认前缀。

ANSI 视图按需加载 [xterm.js 6.0.0](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0) 和同项目的 Fit 0.11.0，使用标准浏览器 DOM 渲染和尺寸观察，适用于桌面 WebView 及浏览器。两个 npm 包固定完整锁文件版本并按 MIT 分发，安装无生命周期脚本。原始字节视图与 ANSI 维持独立，原生平台渲染和体积以候选验收为准。

鼠标报告需单独启用，只接纳当前已聚焦终端在真实鼠标事件内发出的 xterm 报告。旧式单字节报告和 SGR 报告都按原协议字节进入键盘使用的有界 Host TX 仲裁。聚焦点击、设备询问、合成鼠标事件、失焦和视图换代不产生报告。OSC 8 保留各段可点击链接，仅用户激活时通过宿主 HTTP(S) 外链策略打开。当前渲染段中的最近链接也提供可键盘访问的标准链接；OSC 52 仍不产生剪贴板副作用。验收核对真实事件的原始报告、焦点与选区、受限链接及可访问的激活方式。

### 双会话接收对比

工作台从已有的每会话 Raw 读者投影两个当前标签的 RX，复用订阅和留存限额。筛选按 Host 身份、代次、会话和会话代次进行，关闭或撤权时不再呈现旧字节。面板只持有选择、位置和局部解析结果，无新契约、连接、发送操作或持久数据。接收区原有单流文本／HEX 视图继续用于单一来源的解码。

对比用已记录时间、事件号或 RX 字节偏移定位。相邻时间要求同一单调时钟，并在已观测的连续对端 RX 范围内，容差固定为 100 毫秒，显示实际差值。偏移使用半开范围，跳转仅使用已收到的数据。读取缺口和配置切换断开时间连续性。只渲染视口附近的记录，操作联动用真实纵向滚动，目标端定位不会被当作反向用户滚动。用不同长度、缺口、时钟不一致、换会话与撤权覆盖匹配和显示边界。

## 插件字节流传输

签名后台在登记时选择已声明的传输提供器，设备目录发布当前登记。设备标识绑定贡献 ID，打开时复核登记、执行信任、调用者的设备授权和参数 schema。Host 保有逻辑会话、代次、TX 仲裁、原始事件和录制。Node 提供器持有自己打开的连接句柄。

每个实际连接使用独立的有界本机回环线路。Host 通过已认证后台控制管道交付一次性凭据，Node 连接后等待 Host 验证并放行。线路承载本连接的读、写、取消和清理，后台任务身份与用户控制凭据留在原入口。设备 owner 继续使用相同的非阻塞 TX 结算与 Raw 记账，插件只回报可证明的连续写入前缀。撤销调用者授权停止其后续操作和 Raw 交付，设备保持 Host 所有。

工作台打开插件设备时，通过现有连接入口把用户明确提交的参数传给 Host。编辑器保留当前目标的参数草稿，Host 按已签名的传输 schema 校验。连接失败允许原地修订后重试，成功后关闭编辑器，目标或 Host 代次变更时清理旧输入。

后台停用或执行信任撤销等待实际连接回收。认证线路给出的真实关闭确认或确定的所属 Node 进程退出可以解除资源责任。线路失联且清理无法验证时，Host 停止其所属进程。由该进程共同承载的后台经过已有的故障回收，已接纳写入的未知区间继续保留。[专项验收](./acceptance.md#签名插件传输)

TCP 参考传输的主动连接和侦听共用显式设备打开参数。侦听默认绑定本机环回，可选指定本机 IP。侦听就绪后交给 Host 会话负责，首个套接字接入时停止接受新连接。连接前的读取最多等待本次请求期限，写入返回已接纳零字节，不积压等待新对端。对端半关闭时先读尽已到达的字节，再报告 EOF 并结束该会话，重新打开建立新的接收来源。关闭会话、取消打开和停用都等待套接字及侦听器实际回收。首方 TCP 包沿用现有源码归档、精确摘要和签名登记方式，复用固定 Node 与公开 SDK。工作台按已登记的首方包及贡献 ID 选择角色表单，第三方和旧版仍使用插件参数表单。操作仍由原有 Host `device.open` 验权、接纳并指派会话。验证使用独立 TCP 对端，核对收发、空等、端口占用、忙时释放、半关闭及重新绑定。 [Node TCP 接口](https://nodejs.org/api/net.html)

RFC 2217 参考连接复用 TCP 资源监督，并由各会话持有独立 Telnet 解析器及协商状态。会话接纳前要求双向二进制和串口控制选项协商成功，按波特率、数据位、校验、停止位、流控、显式控制线设置逐项等待实际应答。配置不符、拒绝、超时和中途关闭保留发生的步骤及可核对的请求与应答，关闭该套接字。Telnet 帧与线路数据分别解析，只有完成二进制选项协商后的串口字节进入有界接收暂存。工作台的发送结果继续按原始串口字节计数。首方 RFC 2217 作为独立归档随 Host 分发。归档和签名来源按精确摘要固定，复用既有 Node 和 TCP，实现与 TCP、外部参考包各自登记和停用。打开继续经过 Host 现有设备目录、授权和操作生命周期。验收核对源码产物、来源审批、首次登记、重启及实际独立对端。打开失败由已认证的插件传输私有线路在实际清理后结算。Host 给已登记的两个 RFC 2217 提供方留出协议自身的三秒协商期限，只将已知参数、有限的线路码值和原因映射到现有 HostError 详情。连接失败码沿用既有值。操作查询和同键重放仅在 device.open 的结构化失败中保留重新校验后的 RFC 2217 参数证据。桌面和配对浏览器在当前连接表单中本地化具体原因，通用通知与日志继续使用原失败码。实际对端校验配置拒绝、无应答、断连及下次重开。会话内 DTR、RTS 沿用 session.control 的授权、线路值和会话代次。连接完成后声明实际可用的输出线，硬件流控接管 RTS。每次只提交一个 SET-CONTROL。等待应答期间单一 Telnet 读者继续区分 Raw 和控制帧。Host 在控制等待期间继续发布 RX，既有发送租约维护副作用顺序。对端回报有效的不同值时保留请求和实际值。流控暂停期间未提交的命令可明确失败。提交后取消、超时或断线时结算未知并实际关闭，迟到值不能满足下一次请求。保留签名旧版的迁移和停用意图。 [RFC 2217](https://www.rfc-editor.org/rfc/rfc2217) · [RFC 854](https://www.rfc-editor.org/rfc/rfc854) · [RFC 856](https://www.rfc-editor.org/rfc/rfc856)

### Node 消息传输

插件在实际连接打开后确认字节流或消息语义。既有插件继续通过 `read` 返回字节流。消息连接通过 `readMessage` 一次交付一个完整消息，类型为二进制、UTF-8 文本或数据报。私有认证线路的单条消息上限为 128 KiB。无数据、零字节消息、输入结束和失败分别结算。实际会话快照记录本次连接确认的语义。

Host 为每条消息分配标识，按读取和源事件的字节预算分片，保留总长、偏移和类型。空消息分配一个 Raw 事件序号，维持相同的字节游标。捕获与播放沿用 Raw 元数据。单次会话写入交给消息提供方一个完整消息。提供方确认全部或零字节，部分接纳属于无效结算并保留未知范围。超过上限的消息显式失败，连接仍由 Host 和签名插件按现有生命周期清理。

#### UDP 设备传输（NET-02）

UDP 提供方复用固定 Node 的数据报套接字与公开消息 SDK。每个会话只持有一个选定地址族的套接字。单播绑定后固定对端地址及端口，由内核过滤其他来源。IPv4 支持限域广播及指定本地接口的定向广播。IPv4 和 IPv6 组播使用通配地址接收，均要求显式指定入组及发送接口，IPv6 使用数字接口索引。打开会话前完成绑定、连接或组成员配置。许可、套接字占用和实际清理沿用设备打开及停用流程。 [Node UDP 接口](https://github.com/nodejs/node/blob/v26.0.0/doc/api/dgram.md)

接收队列同时限制数据报数和总字节。队列满后保留已入队的前缀，停止接收并结算失败。每次写入提交一个数据报，超过对应协议最大负载时接纳零字节。正常写入回执表明本地套接字已接纳，独立对端才能证明收到。空数据报保留 Raw 事件，UDP 等待期间无数据不改变会话状态。测试用独立对端核对地址族、绑定、来源过滤、边界、接口选择和释放。

#### WebSocket 设备传输（NET-03、CONN-12）

设备 WebSocket 是签名 Node 传输，沿用 Host 设备授权、会话代次、写入回执和 Raw。客户端接受显式 `ws://` 或 `wss://` 地址，按固定 Node 进程的信任配置校验证书，握手不跟随重定向。侦听由用户指定本机 IP、端口和路径，默认仅在 IPv4 回环绑定。每个侦听会话只接纳一个对端，浏览器握手须和会话指定的 HTTP 来源一致。侦听有自己的端口和握手路径，配对浏览器继续使用 Host 的原有授权与控制通道。TLS 私钥及双向认证按 NET-08 验收。

帧解析复用 `ws` 8.23.0，随签名归档提供许可证。限制单消息 128 KiB、帧分片数及接收队列，关闭压缩。一次 `readMessage` 提交一个完整文本或二进制消息，保留空消息和独立边界，Host 记录同一消息的 Raw 分片。会话打开时选择写入帧类型，文本只接纳有效 UTF-8。未接入对端或超限写入接纳零字节，已派发却未获得本机确认时结算未知。对端关闭后先交付已收到的消息，并区分正常结束和接收故障。关闭等待底层套接字实际回收，关闭握手有期限。独立对端核对文本、二进制、分片、超限、关闭和重新绑定。 [ws 协议选项](https://github.com/websockets/ws/blob/8.23.0/doc/ws.md) · [上游队列修复](https://github.com/websockets/ws/security/advisories/GHSA-37g9-w4hg-h9qr)

文件发送和任务面板从同一 Host 操作结果显示请求字节、后端已接纳字节、未知范围和设备确认状态。进度条的分子是已接纳写入，分母是请求范围。速率按两次实际增长的 Host 累计值与客户端观察的单调时间差估算，至少相隔 250 毫秒，5 秒无新量或离开运行状态时停止显示估算。剩余时间按剩余请求字节和观测速率取整。取消调用由既有操作权限核对，用户请求与主操作终态分别显示；任务结算沿用同一操作的累计值和回执。文件源读取量统计校验成功的逻辑数据块，同一块的派发前复核仍计一次。计数与操作的写入证据在同一事务提交，保留期随原回执。Raw 查询 `transfer.readProgress` 沿用回执的源资源读取授权，旧回执缺少证据时显示未知。

桌面拖放在原生窗口接收单个文件路径。文件发送面板以落点坐标确认源文件字段，再用一次性票据按窗口实例和 Host 代次选取文件。Host 沿用原生选择器的单文件注册与授权。工作台展示文件名和发送范围，用户确认后才接纳发送操作。配对浏览器的来源交接和命令槽沿用显式选择及预览确认语义。

### 延时自动应答

协议自动应答复用首方自动化的规则执行器及工作台入口。规则仍绑定一个已授权会话代次，通过版本化条件匹配一次有效请求。定长 HEX 模板使用明确的接收边界，忽略没有完全匹配的帧。延时是观测到匹配后至允许排队写入的最短等待，默认零。观察时限只约束匹配阶段。

定时等待可由原任务中断，等待期间不占用 TX 租约。等待后先复核从匹配来源到当前流尾的连续性，再申请原有事务租约。在租约内再次复核换代、关闭、配置与缺口，随后由 Host 校验当前权限并结算写入。该路径复用既有任务、写入回执和取消清理，避免独立调度或额外进程。单次武装在首次应答或明确终态结束，重新应答按新会话游标武装。

### 环回自检

DIAG-01 与 LINE-15 由一个内置 Node 任务完成，沿用 Host 会话的读取、写入、事务租约和真实写入回执。发起时绑定 Host、会话标识和代次。回环类型取自 Host 对实际会话提供方的确认。虚拟 Echo 和实体 UART 使用同一测量算法及不同来源标记。实体线路需操作者确认目标端口的 TX/RX 短接。未知或远程传输不能标为本机实体 UART。

每帧包含固定格式的种子、帧序号和本次运行标记，之后是由种子与帧序号生成的确定性负载。运行标记用于识别上次任务的迟到回环。单个任务对帧数、帧长和等待期限设上限。在事务租约内逐帧发送，以当前 Raw 游标和本次发送意图定位 RX。子写入已确认完整接纳、源事件连续、回环字节长度和序号符合时，才逐位比较有效负载。部分接纳、未知回执、缺口、额外字节、换代及配置变化中止当次测量。缺字节、序号不符、超时和逐位差异分别有结果。误码率的分母为实际已比较的有效负载位数。保留每帧来源区间、写入操作、计时起止与已核验样本数。往返延迟与吞吐按同一来源时钟计算，时钟不可比时明确显示未测得。

窗口由任务进度和终态显示结果。任务仓复用权限收回、用户取消、租约释放和原会话结束的处理。测量失败后重试须另行发起，不自动重复写入。使用 Virtual Echo 和可控测试对端检查字节、拆包、异常与取消，再单独核对实体短接。实机与发行证据按适用环境记录。

## 生命周期与资源责任

- **设备与操作**　Host 持有逻辑会话、租约、TX 仲裁和关闭责任。系统串口句柄归 Rust，插件传输后端可持有自己的句柄。独占工具接管系统串口时，先冻结新写入、结算在途事务并关闭旧句柄，交还时重新核对设备身份。持久接纳、实际派发和最终回执分别记录。窗口关闭或停止等待后仍须结算 I/O，partial/unknown 保留已知范围且不自动重发。见[流与操作](./contracts/stream-and-operations-v0.md)。
- **Raw 与录制：** 源环、各 reader、录制和 UI 显示有独立游标与预算。慢读者产生明确缺口，不能阻塞采集；窗口隐藏或查看历史不冻结 Host。保留未 ACK 批次的预算，实际完成写入或退出才释放。录制按[容器契约](./contracts/capture-container-v0.md)保存验证前缀，回放不创建设备或发字节。
- 打开固定录制时，**Host 重建回放索引**并在限制内逐条累积已通过验证的卷号、偏移、长度和摘要。搜索与跳转共用该只读索引，回放关闭后释放。清单状态、卷长度、摘要链、逐记录摘要、来源、原始序号和登记指纹仍须通过校验。录制验证、追加、恢复和导出继续检查原索引，索引重建不修改录制目录。
- **录制授权：** Host 的录制 reader 绑定源会话的 `content.read` 和目标文件的 `workspace.modify`，监控这两项实际生效规则及期限。追加目标文件的读取权时，录制仍由原权限继续。批次入队与撤权共享授权锁，磁盘写入在锁外完成。撤销或替换任一绑定规则后，停止接纳新批次并失败结算，已合法入队的数据可完成落盘并供验证与恢复。撤销后重新授权只对新录制生效。客户端 Raw 批次沿用创建时的身份授权代次。
- **授权与晚结果：** admission、dispatch、存储提交和最终交付分别复核当前授权。派生结果保留源权限，撤权后不能从历史结果或文件引用绕过；订阅只接纳当前身份和代次的帧。窗口级设置效果、媒体票据、读者和计时器随所属代次退休。
- **图表文件结果。** Host 按签名动作的输出声明解码 SVG，把原始字节交给现有结果库和操作终态。桌面和 MCP 用同一文件引用读取，沿用来源授权和内容指纹。客户端通过明确的保存操作交付文件。
- **文件与恢复：** Host 登记用户明确选择的位置或固定内容引用，前端不提交任意路径。窗口图库持有引用而非原文件；共享背景选择、窗口元数据分别持久化。写入保持原子、revision 冲突及未来格式保护。[ClientState 恢复](../src-tauri/src/recovery.rs)只在明确重启时归档原件并安装候选，不重置 Host 数据库或删除用户文件。

本机用户控制入口通过 `session.toolHandoff` 提交已签名包的工具 ID、安装 revision、归档摘要和明确的会话代次。Host 先在原生提供器内为该设备保留独占预约，再由原有调度器取消并结算旧代次的在途请求。预约跨越句柄释放、工具执行和重开。Windows 参考执行者在受监督的 Job 中启动单个已验证工具，只传入核对后的串口地址。工具进程确认退出，或旧句柄已确认关闭且取消或到期阻止了工具启动时，Host 按当前授权重新枚举设备。匹配唯一强身份后按原会话保存规则重开并分配新代次，回执保留工具操作的实际结果。原绑定在新代次沿用原打开者的授权戳和工作区配置复核，授权和绑定有效时登记原自动重连策略，已停止的策略保留其状态。所有权无法确认时保留原生预约和失败回执，旧 TX 结果沿用原有证据。

## 顺序帧模板

IO-14 的模板沿用字段编解码和校验算法。模板描述帧头、长度、序号、负载、校验和帧尾的固定顺序。序号及可变长负载从显式命名变量取值。长度按配置的字段范围计算。先确定长度和变量的最终字节，再计算校验。模板与变量都用有界数据描述，Node 和工作台可使用同一解释器。

解码使用完整帧字节确定负载范围，再核对固定帧头和帧尾、长度字段与校验。结果保留零基半开范围、最终 HEX、变量或覆盖区间。预览只处理主动提供的字节，发送沿用工作台原有提交和授权边界。

## 脱敏录制

LOG-07 与 SEC-02 使用同一份规则定义。规则按顺序替换 UTF-8 文本中的匹配，替换值按字面使用。Host 复用已锁定并随项目发行的 Rust `regex 1.13.1`，在文件写入边界执行。有界的正则编译和输出预算适合串口持续输入。桌面预览、CLI 和 MCP 都通过同一 Host 验证与应用规则。

实时录制按来源、代次、方向和配置分别拼接由换行终止的文本。连续分块可组成一条完整记录。开始时落在行内、遇源缺口、换代、非法 UTF-8、超过预算或停止时尚有残行，只保存略过状态与来源位置。遇到规则失败，终止本次脱敏录制。预览使用请求者主动提供的样例，结果仅返回请求连接。用户预览和规则错误均无原始流副本或可跨连接读取的结果引用。

脱敏容器使用单独的格式版本，记录规则摘要、变换标记、来源位置和处理后的文字。发送内容标记为 TX 尝试，发送结算仍来自操作回执。验证、恢复、尾部读取和导出明确识别变换记录。脱敏回放按文字记录显示，协议解析与原始字节操作沿用原始录制。原始录制可由用户另选目标发起。录制仍绑定源 `content.read` 与目标 `workspace.modify`，读取与导出在交付边界检查当前授权。

脱敏续录从正常结算清单的 `redactionResume` 接续。生命周期、发送回执和控制事件可以经过录制线程而不生成变换记录，因此每个源的游标在整个已授权批次处理完成后推进。清单按来源顺序保存处理游标和可确认的各方向行末。追加前核对完整性、来源、代次、配置和同一套规则摘要。旧卷或恢复副本缺少可信位置、位置倒退或规则变化时保留原件并拒绝追加。暂停期间有新事件时保留 `capture_paused` 缺口，并使该源的行边界重新同步。游标连续且新分块与已确认行末的字节位置、配置相符时，首条完整新行可以立即录制。边界不明时把残行记为略过，直到下一个换行。

## 可信 Node 扩展

发行包复用已随包发行的固定 Node。默认脚本、协议扩展和自动化共用 JS/TS、公开 SDK 和任务模型，随包插件交付预构建的 JavaScript。脚本运行与调试在独立 worker 或子进程内进行，Host 按当前会话授权提供设备 API，脚本执行信任独立确认。Lua/Python 适配和第三方烧录工具按用户所需场景另外安装或配置版本、来源和路径，由同一任务监督及授权边界管理。发行验收分别核对默认安装资源和可选扩展的体积、版本、平台及离线依赖。

发送序列、测试用例与数据表优先使用可编辑、可版本化的结构化定义，录制、定时和规则触发提交到同一套任务。需自定义协议编解码或流程逻辑时再调用已审阅的 JS/TS 扩展。编辑器、命令行和任务记录共用输入及结果语义。

规则条件以完整的 UTF-8 行或按字段模板对齐的定长帧求值。未知行边界从下一个换行开始，定长帧需要调用方确认起始对齐。正则匹配使用带时限的固定 Node 执行上下文，数值比较沿用字段解码的原始码值与标定语义。规则按 Host、会话代次和规范化条件在 Node 工作线程间去重。每次武装产生至多一个匹配，保留会话代次、事件和原始字节范围。来源断档、配置边界、会话结束、时钟来源变化或不连续字节会中断观察，副作用由 Host 的作用域和终态负责。工作台可按当前 Host 目录提示动作与会话目标不匹配。手工武装命令规则前先用同目标、同参数检查动作权限，再读取会话最新游标和检查整项规则。检查以窗口现有中止信号控制，不产生操作。匹配后仍由 Host 按当时的授权和同一会话重新判定子动作。

引入外部运行时前，以可复现的脚本或库确认现有 SDK 与 JS/TS 无法覆盖的需求。适配器按平台说明版本、来源、授权、离线安装和增量体积。默认安装的资源清单应继续只有固定 Node 这一套脚本运行时。

首方自动化归档登记周期发送、命令序列、规则触发和日历定时任务。独立安装的参考包继续提供同语义动作。两者共享实现、固定 Node 和 Host 授权。首方包升级以已发布的归档和签名收据识别前驱，保留启用、停用和卸载状态。首次启动、重启和拒权由原生验收核对。 发行体积记录分别列出当前归档、嵌入的前驱归档和安装包。历史归档随版本增加时，评估使用签名描述和实际已安装归档的摘要来核验前驱，并用相同的升级、伪造拒绝和离线恢复场景对照。

命令序列在动作执行前编译一整份有版本的 JSON 定义，预先校验分支、变量、字节、循环深度、最大步骤数和累计等待。参数名和占位符沿用命令库，变量按本次任务快照展开。每个发送或发送应答步骤持有自己的事务租约，延时和下一分支在前一轮租约释放后执行。默认遇应答超时、字节不符、流缺口或未确认写入时结束。显式超时分支只运行无应答补救步骤，任务保留超时结果。发送前从调用者提供的当前 Raw 游标核对已锚定会话的连续性，过期游标、缺口和配置边界都会停止后续写入。工作台用同一编译器预览展开后的字节、延时和应答分支。开始时从当前附着读取游标，任务由 Host 独立执行。关闭面板停止本地观察，重开可接续已接纳任务。结果保留发送回执与已验证的来源。

手工发送录制绑定当前附着、会话代次和配置修订。操作者显式开始和停止，录制期间的手工发送由 Host 核对修订。发送区和接收选区的显式确认共用录制和回执校验。接收选区未确认时不登记动作。确认框可独立停止等待，录制按自己的生命周期观察已接纳写入。录制用终态回执的单次相对区间确认完整 TX，按提交顺序检验发送流绝对区间相邻，遇到证据缺失、写入交错或超过序列限制保留连续前缀。每条录制发送保留原写入期限。最大 5 秒的写入预算为现有事务租约内的排队、应答与结算保留时间。等待取上次完整写入被观察到与下次提交之间的工作台单调时钟差。生成结果交给既有命令序列编辑器，记录与文件另存分别由用户触发。录制启动时可显式选择按发送引用保存。版本 1 草稿的 `variables` 用 `null` 声明无默认值的输入，关联步骤仍用现有变量模板。录制仅以原字节校验确认回执，引用草稿保留顺序、原期限和名称。工作台在当前编辑器内收集临时 HEX，导出和未保存草稿只使用原定义。运行前解析所有输入并编译普通版本 1 定义，固定签名执行器继续接收现有契约。换定义或关窗清除临时输入。串口发送证据仍按会话的记录策略处理。字节引用可通过当前客户端的文件选择绑定，使用与序列导入相同的本地 File 入口。限制为现有单帧 256 字节，按原始二进制读取，仅在当前编辑器保留临时值和字节数。选择或导出不提交 Host 操作，导出只留引用。每次打开由操作者重绑文件，无需跨机复用临时句柄。关闭、替换定义和作用域变化隔离晚结果。系统密钥解析和按范围传输的长文件动作另按对应权限契约验收。

自动化断言分别记录写入终态和设备应答。命令序列可为超时显式配置最多三组请求和期望应答。配置方确认设备支持该动作的重试语义，并使用可区分的请求和应答。每次尝试重新取事务租约，核对同一会话代次、配置修订和连续 Raw，完整终态回执与有序 TX 源证据成立后才允许按应答超时推进下一次。夹入其他写入、源缺口、应答异常及部分或未知写入停止后续尝试。报告保留每次尝试的定义位置、操作 ID、结果和已匹配的 RX 区间。相同、互相包含或旧帧尾部与新帧头部重叠的应答帧由预校验拒绝。已收到旧帧前缀而耗尽等待时，停止在原尝试。超时未确定归属的应答保留到序列结束，后续步骤和分支如期待与其重叠的帧，在写入前报告归属不明。权限撤销、租约失败和任务取消由父操作报告。

测试套件由当前工作台窗口组织独立的命令序列，沿用已登记的签名动作，无需新运行时或首方归档。先校验套件及所有用例。每次接纳前取得当前 Raw 游标并读取权威配置修订，锁定同一 Host、会话代次和配置。随后发生的配置边界由签名序列按该游标核查，事务租约与授权继续由 Host 确认。每个用例以同一操作的终态和经摘要核验的结果结算。首个失败、未知结果或尚有未归属应答时跳过后续用例。仅证实写入的步骤也可能留有应答。当次只以实际回执归类，前次存在未归属应答时同一窗口须确认对端已结束上一轮并重新打开会话，才能运行新套件。停止请求禁止后续接纳，同时按实际操作 ID 请求取消当前项，只有真实取消终态进入取消栏。窗口关闭、断开或会话换代停止后续编排，已接纳用例仍按现有独立任务契约结算。XML 和 HTML 从同一份报告生成，导出不包含发送字节或用例正文。同一窗口按会话和套件定义保留最近四组趋势，每组保留最近八次报告，供 HTML 导出。

参数化用例在版本 1 的 `data` 指定 CSV 或变量表。每个绑定将一个列名映射到序列变量，并声明 `hex`、`u8`、`utf8` 或 `text`。前三种分别生成十六进制字节、一个十进制字节的十六进制表示、UTF-8 字节的十六进制表示，文本类型保留字面值。绑定只覆盖本轮对应变量，未映射的序列默认值继续生效。工作台按用例和输入行顺序展开，全套最多 16 轮，每轮在任何 Host 写入前完成编译校验。每轮清楚记录 CSV 记录开始的物理行号或变量表数据行号。报告沿用真实终态和 Host 操作 ID，保留跳过轮次的来源。CSV 替换校验通过后才更新当前草稿。数据驱动趋势按含输入源的整份套件定义归属，替换 CSV 后，只显示该输入的运行结果。导出的 JSON 保留输入源，报告保留位置和执行结果。

任务内的会话钩子显式使用现有 Node Raw 通道。每个任务最多持有一个有序读取者，与普通读取者共用 Host 名额。读取者绑定原 Host 实例、会话代次和内容授权，持有该代的源直到任务收尾或主动释放。Host 在发送字节、留存缺口游标和会话终态前复核权限。关闭或故障之后，源等待已发布的 TX 意图收齐结算，再从最终游标交付终态。读取者超出留存时须先处理缺口，之后才继续分发事件。

日历定时任务使用资源 Host 持有的 Node 操作与固定运行时的时区数据。定点以明确偏移表示，cron 按所选时区解释。夏令时跳过不存在的本地时刻，重复时刻只执行较早的一次。等待期间不持串口租约，同一 Node 后端最多等待两个日历任务。预期时隙超过两秒仍未派发时，跳过到当前时钟之后并记录受影响区间。等待期间回拨会继续等待。已经提交的子操作如果因回拨落出窗口，确认零写入后结算为错过并保留回执。每轮通过 Host 向相同会话代次提交带修订及绝对日历窗口的写入。Host 初次检查窗口后冻结单调截止点，并在设备派发前重新检查墙钟与单调截止点。超窗回执必须确认没有写入才按错过计入结果。每轮先结算再继续，结果不确定时结束。等待和取消依从现有任务监督。工作台窗口保留按 Host、实例和会话代次归属的接纳引用。重开时按原操作 ID 重新验权查询。重启后由操作者重新确认并武装未来计划，恢复不自动重派旧写入。

重复发送由可信 Node 任务持有单调计划，Host 独立管理每轮 TX 子操作与短时事务租约。超出一轮的定时器暂停及应答跨过的时隙顺延到下一可用时隙，轮间等待释放租约。收字节触发在当前源尾部起算，绑定会话代次和连续原始字节。已接纳的写入仍由 Host 结算，部分写入、缺口或应答异常结束后续轮次。该动作和顺序应答共用同一份 Raw 证据读取。

Host 主动关停时先用 `HOST_CLOSING` 关闭插件按需激活准入，再通知运行时与恢复监督器退出。关停前已由监督器确认的故障继续保留原有错误。关停与待入队请求共用同一准入锁，已完成预核的请求也须遵循最终准入结果。

插件安装与后台恢复共用变更名额。恢复正在持有名额时，已接纳的安装沿用原操作预算排队，恢复归还名额后重新核对调用者、文件引用与版本。取消等待按同一操作结算。人工管理占满名额时，其他操作仍按原容量规则返回。

任务内读取原始流时沿用 Host 的留存窗口、事件和 reader 内存预算。Node 私有管道用长度头区分 Raw 和控制，分别保留收发名额，writer 在帧之间优先处理控制。已开始写入的 Raw 帧有固定大小上限。Raw 页的内存租约随 writer 保留，发送前复核任务与授权。验收检查慢消费者、取消与撤权时队列和工作归属。

原生 Node 管道的控制、Raw 和派生队列保留各自的容量。成功入队会唤醒 writer，控制帧仍优先，Raw 与派生帧仍交替。业务请求、入站帧及异步 Raw 或派生结果就绪时唤醒 owner。Unix 读写等待管道就绪，每轮在原有间隔内重查停止信号，保留非阻塞回收边界。用真实派生发布、Raw 录制、撤权和进程退出核对吞吐与生命周期。

macOS 监护按子进程事件类型确认退出。初始暂停期间继续等待 Host 核验映像签名并发出恢复命令。恢复运行前观察到的真实退出由监护回收并写入 Host 私有诊断。验收覆盖正常启动、错误签名拒绝和实际退出。

派生输出由 Host 按生产 Operation 和精确会话代次留存。Node 发布在独立队列接纳，Host 对照留存原始事件核验来源，以实际处理器和规范化配置生成追溯信息。读取方使用各自页游标并复核源内容权限，留存范围不足时明确报告游标过期。派生缓冲和读页预算与原始流、录制分立。验收覆盖派生积压期间的 Raw、控制与录制，以及撤权、旧代次和过期读取。

协议解析器由签名清单声明，并由后台通过公开 SDK 注册处理器。Host 按会话读取权限在同一动作目录公开解析器，复用任务、派生流和进程监督。关闭图表视图不撤回后台处理器。停用或撤销执行信任撤回登记，已验证的派生样本仍按原来源授权读取。 [协议解析器契约](./contracts/node-extension-v0.md#协议解析器)

通用分帧（PROTO-01）沿用签名解析器的会话读取授权和任务取消。帧状态属于本次解析任务，保留精确 Host、会话代次和原始事件及字节范围。固定长度、分隔符、长度字段和静默间隔定义候选边界，帧头、帧尾与转义按配置参与匹配。静默以相邻接收事件的同源单调时钟计算，无法推断同一收块内部的线路间隔。缺口、代次或配置变更结束当前连续段，未完成的帧单独记录。上限约束输入、未决帧、输出大小和扫描时间。验收核对拆分与合并输入的一致结果、带边界的噪声恢复、超长拒绝、取消和可追溯的范围。

帧字段定义以封闭版本描述帧长度及各字段的字节范围，位域按字段端序表示的整数从最低有效位编号。字段编解码共用同一份已验证定义。整数字段及其十进制比例、偏移使用精确算术，避免 64 位原值转为浮点后丢失。浮点字段使用指定的 IEEE 754 宽度，拒绝非有限值。枚举绑定原始整数，单位与校验覆盖区间随结果交付。冲突范围和校验循环在读取或构造前拒绝。解析保留字段相对于帧的字节位置，上层可用已验证帧来源定位至原始记录。验收对照两种端序、边界值、共享字节的独立位域、互逆构造与坏校验。

字段编解码由独立随包 Node 插件公开，和工作台复用同一 TypeScript 实现。插件处理调用者明确提供的 JSON 或 YAML 定义与字节，结果中的字节位置相对输入起点。工作台使用经验证的分帧结果换算绝对位置。两个动作在会话作用域检查当前内容读取权限，构造结果只返回字节预览，实际发送沿用独立授权和发送入口。分帧包与字段包分别锁定归档、密钥和首次登记标记，同一产品来源名不扩大任一密钥的信任范围。

协议字节分色使用已验证帧和编译器返回的字段半开区间。字段覆盖同一字节时，当前选择优先显示，未覆盖区保持原始 HEX。展示角色只保留于当前定义的界面会话，定义失效时回退到完整原字节。只读回放沿用录制源偏移，构造的字节预览单独标记并从 0 起算。

工作台构造可从全零字节开始，也可基于已验证的接收帧保留定义未覆盖的字节与位。预览同时呈现生成字节和同一定义重新解析的结果，生成范围从 0 起算。定义、源帧或字段值有变化时，旧预览立即失效。数值草稿使用字符串承载 64 位整数与十进制工程值，使用定义的宽度、符号与端序验证输入。纯本地预览不依赖串口会话。

CRC 识别对用户明确给出的覆盖字节与校验字节计算，和发送校验共用计算内核。目录限定可识别的多项式、初始值、位反射和末异或。校验字节按所选端序解释，非整字节宽度使用右对齐表示。相同覆盖字节只计作一个样本，给出不同校验值时报告矛盾。单份样本或多个候选时要求补样本，结果只说明与目录候选一致。工作台支持本地预览，随包 Node 动作沿用字段包的会话读取授权。

Modbus 模板对完整帧分别验证 RTU CRC、ASCII LRC 和 TCP MBAP，再按明确的请求或响应方向验证 PDU。三个封装共用同一套零基地址、数量、数据与异常规则。串行单元 0 只接受写请求；TCP 单元标识按 MBAP 保留。工作台构造用于预览，随包动作沿用会话读取授权。实时时序、会话独占、发送、广播完成及迟到响应由后续事务层结算。 [应用协议](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) · [串行规范](https://www.modbus.org/file/secure/modbusoverserial.pdf) · [TCP 实现指南](https://www.modbus.org/file/secure/messagingimplementationguide.pdf)

离线配对验证请求帧。串行广播直接根据是否提供响应样本判定，其他请求先验证响应帧再核对功能码、单元标识和 TCP 事务 ID。TCP 默认按网关核对单元标识，直连设备可显式忽略该标识。读响应核对请求数量及位数据填充，写响应核对地址、值或数量的回显。已配对的设备异常、字段不匹配、串行广播和样本缺失各有独立结果。缺少样本仅说明输入状态，实时超时由事务层计时。随包动作继续只持有会话读取授权，纯工作台比对读取用户输入。

Modbus 从站模型按单元配置线圈、离散输入、保持寄存器和输入寄存器的零基范围。四张表独立，未映射的空洞返回地址异常。解析器先核对完整封装与目标单元，再解释功能码和 PDU。模拟写入在完整范围校验后更新副本，正常响应回显对应字段。串行广播更新适用范围并保持静默，非法请求不改变模型。工作台保存当前预览模型，随包动作由调用者传入状态并取回下一状态。后续实时适配器负责会话独占、计时和状态归属。 [应用协议](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) · [串行规范](https://www.modbus.org/file/secure/modbusoverserial.pdf)

Modbus 主站参考动作使用已有签名自动化包的会话权限和事务租约。解析与预览包继续使用读取权限。同一逻辑请求只允许一次发送在途，收到完整 TX 回执后在同一会话代次核对原始事件。TCP 用 MBAP 长度，ASCII 用定界符，RTU 用已知响应长度和 CRC 汇集分块。响应匹配成功、设备异常、无效帧、迟到响应及数据源变化分别结算。延迟以同一 Host 源时钟的 TX 完成与最后一段 RX 为基准，保留两端精度及原始字节区间。串行广播持有租约等待设备处理。有界重试默认关闭，显式允许时仅对 FC01—04 读取生效。Host 在同一事务租约中按顺序发送，确认完整 TX 并耗尽响应及迟到窗口后才允许重发。已收到匹配迟到帧、帧边界无法确认或来源变化时结束动作。TCP 重发使用递增并回绕的事务 ID，串行重发收到的帧只归入同一个逻辑请求，报告标记尝试归属不确定并省略单次耗时。动作预算必须能覆盖全部尝试并留出释放租约的时间。工作台的主站时序从已打开且可写的会话显式发起，沿用目录、操作权限和精确候选回执。时序图只画 Host 确认的 TX 与匹配帧的 RX 首尾事件，记录各自时钟和精度。样本抖动对照同一会话、请求与源时钟中的已归属首发耗时。Modbus 主站由独立的首方签名包供货，启动只登记会话动作。打开可写会话后仍由 Host 核对目录、当前租约和 device.modify 权限，再由用户显式发送。沿用首方包的档案摘要、来源隔离、重启恢复与用户停用决定。独立安装的自动化参考包保留自己的动作和来源，便于复验。

工作台的 Modbus 寄存器视图与主站时序复用同一动作入口和结果归属检查。界面将一基地址换算为零基 PDU 地址。每个寄存器字沿用报文编码，变量的字节与字顺序只影响工作台对一至两个寄存器的解释。监视每次等 Host 结算后再开始计时，停用包、离开视图或收到异常会停止安排下一次读取。手动写回保持寄存器时按变量宽度发 FC06 或 FC16。匹配的写响应显示为设备回执，下一次成功读响应才更新表值。 [Modbus 应用协议](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)

帧异常检查把签名分帧动作经摘要验证的结果与工作台留存的 Raw 事件关联。长度和校验条件沿用用户字段定义。序号按字段位宽回绕，以限定的向前距离区分缺帧与跳变。坏帧阻断序号和重复推断，来源断档及字节区间空洞阻断相邻帧比较。帧间时限使用同一 Host、会话代次、配置和源时钟的时间，末尾判定要求范围内还有真实事件。来源证据缺失的区间单独标记。

总线负载（VIZ-10）按一条会话的单调时钟统计最近 60 个定长窗口，RX 计入后端采集区间，TX 只计最终回执中的确认字节，未知字节单列。分帧以同批留存 Raw 的连续来源与实际字节核对，并按帧末接收时间计入窗口。协议错误率分母为核对通过的分帧，分子为字段定义解析失败或校验异常的帧，每帧只计一次。采集及读者缺口、帧页覆盖不足与最后未观测完的窗口不外推速率。续页游标或回放帧锚点只覆盖其后的分帧范围。块内游标和同一时间刻度内未纳入本页的前序帧会使首窗分帧覆盖不足，完整的原始事件率仍可查看。源时钟、时间范围及最粗原始分辨率随视图显示，独立线路仪器的错误率保留为待验指标。

字段曲线（VIZ-16）从已验证分帧页和同批留存的 Raw 事件建立点与字节的对应关系。按会话、实例、配置和实际字节核对帧来源，字段跨收块时分别记录每段。曲线使用当前页的帧顺序，游标保留精确字段值、原始码值和标定版本。坏帧、来源缺口与标定表外值形成断点。曲线压缩只减少显示点，游标仍以原帧为单位。验收覆盖跨块字段、筛选或压缩后的点选及留存缺口。

HEX 接收区和字段曲线交换同一组选区端点。每个端点以 Host 实例、会话代次、事件和绝对字节定位。实时来源沿用已经授权的同一 Raw 订阅，独立保留原事件及精确裁剪的字节范围，受当前接收字节预算和 16,384 条事件上限约束。合并的显示行按字节偏移转回原事件，较早的选区在其附近初始化扫描窗口。曲线返回接收区时重新核对留存、事件顺序和实际字节，再冻结目标快照、显示精确选区及原接收行。跨显示行或端点尚未渲染时直接选中已验证的短 HEX 摘录，避免把中间的其他来源及行标题并入选区。切换会话或回放读页会使旧跳转失效。离开字段编辑沿用未保存工作协商。验收双向入口、跨收块选区和已移出留存的目标。

接收选区保存（DISP-20）从当前已授权的连续 HEX 或 ASCII 选择读取原始字节，限制为 64 KiB。选择格式、主题或 SVG 页只影响展示。保存前再核对留存字节、方向与绝对偏移。HTML 和 SVG 复用同一行映射，ASCII 逐字符转义，输出自包含文本与静态图形。前端在显式保存后沿用系统选择器与原子写入，配对浏览器在本机下载。

只读回放中的字段曲线读取当前已加载的录制记录。用户选择原始来源和固定帧长，并以已知帧起点建立边界。已知字节范围的录制缺口放弃未完成帧，此后根据同一配置的绝对字节偏移定位下一个完整帧。范围未知的接收缺口和配置边界结束当前解析范围。游标同时显示来源事件和录制序号，输入来源事件和字段区间内的任一字节可反查曲线。回放读取权限、引用摘要和定位代次沿用既有读页入口。

会话对比（PROTO-11）复用只读回放的固定帧起点和原始字节核验。帧位置按选定锚点及帧长计算，已知采集缺口保留缺失位置。对齐可按位置、原始字节前缀或一至四个协议字段的原值选择，重复键按出现次序配对并标明重复。逐帧以内存中的半开字节区间表示变化，字段变化独立保留解码值及原值。时间差使用各自首个完整帧到当前帧的单调时钟耗时，跨采集缺口、时钟或不连续记录的时差留空。每侧最多 128 帧、64 KiB。工作台仅保留用户从两次回放明确选定的分帧结果，记录绑定当前工作区、Host 附着和各自回放会话代次。每侧通过 `replay.read` 的同目标权限观察后才显示，权限消失时清除样本。对比本身不推进回放游标。随包字段动作对调用者显式提供的帧段执行同一模型，沿用调用目标会话的内容读取权限。摘要覆盖整个有界窗，分行分页明细保留半开字节区间、原始字段与解释值。旧 0.1.0 和 0.2.0 归档仍以各自摘要和来源标识识别，升级到 0.3.0 复用原启用、停用或卸载决定。

基础图表统计（VIZ-05）取当前筛选范围的有效点，在渲染压缩前求最小值、最大值、均值、总体标准差及 P50/P95/P99。分位数按排序后相邻样本线性插值。实时字段曲线按已识别帧计数，固定帧回放按首末帧之间的字节对齐位置计数。签名参考图表按当前留存窗口的派生位置计数。各分母均纳入能定位的缺值，数量未知的采集缺口保持原有提示。

高级统计窗口复用受信统计扩展的 Host 动作。样本值可用安全整数或十进制字符串，后者与频谱及跨源 XY 的值编码一致，计算以有限双精度进行。展示前按所选范围核对逐窗的纳秒和样本半开边界、尾窗以及计划、有效和缺值关系。报告由同一操作及归档摘要绑定，缺值率只使用该窗口的计划采样数作分母。

高级统计扩展以调用者声明的单源采样格为输入。调用者传入首序号、预期槽位数与已知有限数值。窗口可按槽位计数，也可按一个单调时钟和固定采样间隔计算。宽度与步长独立，可形成滚动、重叠或分段窗口。边界左闭右开，尾窗按声明范围裁剪，输出时间与序号区间、预期数、有效数、缺值数和统计量。没有计划样本的时间窗口返回空缺值率，有计划样本但全部缺失的窗口返回 100%。扩展只处理调用参数，市场签名及实际安装按市场流程验收。

专业频谱扩展（VIZ-04）读取调用者声明的等间隔采样格与有效值。精确序号及相对时间保留为十进制字符串，频率栅格由采样间隔及 FFT 点数计算。每行瀑布数据记明实际窗口、缺样及跳过或补零结果。矩形或周期 Hann 窗按系数和校正幅度，单边频点除直流与 Nyquist 外计入共轭幅度，输出以一个输入单位为参考的 dB。零幅度保留空值。尾部不足窗单独计数。直方图基于实际值，可以按观测范围或声明范围分箱。箱右界不计入本箱，最后一箱包含上界，并单列上下溢出。受信插件详情通过同一报告读取流程验证 Host 目标、包摘要和结果文件指纹，再用完整报告计算统一的 80 dB 显示范围。超过显示边界的数值仍可按频点原样查看。 [SciPy 频谱分析](https://docs.scipy.org/doc/scipy/tutorial/signal.html#spectral-analysis) · [SciPy 周期 Hann 窗](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.windows.hann.html)

基础 XY 和散点（VIZ-06）从同一个来源帧取两个有效数值字段。坐标轴各自按有效配对的范围缩放，常量轴居中。XY 连线遵循原帧顺序，遇到无效点、采集缺口及来源变化时断开。筛选保持原始帧索引，图上的点和键盘帧游标可以回到两个字段的原始字节。跨通道时间配准及插值由高级分析扩展处理。

专业 XY 扩展只读取调用者给出的两组源样本。共享单调时钟直接配对，独立时钟需要一对同步基准校正偏移，或两对基准计算线性漂移。以 X 的实际样本为输出行，使用整数有理数比较时间，保留原样时间戳。每行显示精确匹配、线性插值或缺失原因。插值同时保留两个 Y 源样本、输入索引和精确权重分数，数值运算采用二进制双精度。明确的缺口、空值及超过设定间隔的区段禁止跨越，首末范围以外保持缺失。结果标记连续曲线应断开的位置，供专业视图与离线审计共同使用。插件详情的专业 XY 面板在对应包已启用并获得执行信任时显示，提交的输入由选中 Host 的公开动作处理。工作台按完成操作、Host 和依赖归档摘要核对结果引用，逐页验证报告摘要后绘制，并保留两个时钟、同步基准和点位证据。插件代次或打开页面变化会结束本地等待。实时分帧与只读回放按当前筛选范围暂存通道，每轴最多 128 帧，取已验证帧末的源单调时间，保留十进制字段值、缺口、帧及录制定位。缺少可核对时间的帧跳过并计数，下一点断线。采样可同刻，Y 出现同刻多个候选时报告歧义并断线。不同 Host 或实例上的同名时钟仍须校准。暂存绑定当前窗口、Host 连接、来源会话代次和实时 Raw 订阅读者，回放使用当前打开的回放会话核对权限。权限观察失效、会话关闭或换代、订阅更新及切换到局域网对端时，移除相应样本、载入的输入和报告，停止等待在途结果。用户显式分析前复核两个来源的权限。编辑过样本的报告只显示重新计算后的结果。

字段图表 CSV（VIZ-13）使用点击导出时的筛选范围、轴和已核对的帧快照。渲染压缩只改变屏幕绘制。起止事件与字节位置使用半开区间，并按原始十进制字符串导出。字段跨事件时使用单元格内的 JSON 数组保留各段原始 HEX、区间及回放序号。未知缺失量留空，缺乏来源证明时保留图表帧索引和无效标记。GUI 保存沿用原生文本导出的目标选择和原子写入。首方电压图表的离屏 CSV 则由签名动作读取精确会话并保留原始十进制电压、事件及字节区间。Host 将 Base64 结果解码为同一份有界 UTF-8 文件。MCP 通过结果引用读回，桌面沿用 SVG 的工作窗口代次、会话授权和对话框返回后的文件读取，再原子写入用户选择的目标。离屏 PNG 复用 SVG 的采样坐标和刻度，用固定 Node 的 zlib 生成 640 × 360 调色板图。刻度和轴标题使用有限字形，随包无需系统字体或额外原生模块。Host 验证 PNG 签名与大小后保存字节，桌面和 MCP 共用这一结果。 [PNG 规范](https://www.w3.org/TR/png-3/) · [Node zlib](https://nodejs.org/api/zlib.html#zlibcrc32datavalue)

M5 专业 MDF4 导出接受明确的图表快照，使用同步时间主通道和每行的精确纳秒辅助通道。不等间隔和相同时刻按原顺序保存，缺值使用 MDF 通道无效位，64 位有符号或无符号列直接写入整数。工作台以帧末尾的留存 RX 时间计算单一时钟的纳秒差，并保留原帧号、事件和字节范围、断点与回放记录号。缺少时间、源时钟或配置不一致时拒绝整批导出。保存使用当前实时或回放会话授权，回放数据用原录制的源身份核对，文件保存原录制的序号。Host 仅按已签名动作的文件结果处理，保持大小边界和会话读取权限。 [ASAM MDF 技术说明](https://www.asam.net/standards/detail/mdf/wiki/)

版本化标定沿用字段编解码。线性系数使用与旧比例和偏移相同的数值路径，整数与位字段的查表映射使用十进制定点计算。查表可用离散点，也可在严格单调的相邻点间插值。构造仅接受反算后能得到同一规范物理值的输入。表外解码保留原值、字节区间和标定版本，标为未映射。标定始终基于原始字节，录制与重放保留原报文。

字段随包升级仅接管已登记且匹配内嵌前序归档的安装。安装复用已有快照的 revision 和 CAS。权限完全一致时保留已有执行信任和启用状态，已卸载配置由原登记标记保留。前序归档随候选保留，用于验证中断后的旧安装。桌面发行回退单独验收。

Modbus 实时从站使用独立首方包和当前已打开会话。显式启动后，从最新 Raw 游标接收新请求，使用单个可续期的事务租约按顺序结算回复。会话变更、游标断档及其他所有者实际写入会结束任务。任务中的地址表按合法请求更新，成功结算的结果携带下一模型和原始请求范围。子事务租约跟随父任务授权。父任务取消后，Host 重新核对授权，回收租约并等待已经接纳的子操作结算。工作台区分停止请求与已确认终态，并保留最后一次已确认的地址模型。

TCP 使用 MBAP 长度，ASCII 使用定界符，RTU 使用已支持功能的固定或声明长度以及 CRC。读块发布时间用于追溯来源，独立设备的字符间静默继续按实机验收。任务受总时限、帧数和原始字节量限制，通过 Host 确认实际 TX 后才处理下一请求。广播更新模型并保持静默，发送结果不确定时结束任务并保留已处理范围。实时从站使用已打开的链路，连接管理归 Host。 [串行规范](https://www.modbus.org/file/secure/modbusoverserial.pdf) · [TCP 实现指南](https://www.modbus.org/file/secure/messagingimplementationguide.pdf)

NMEA 0183 模板由工作台与随包 Node 动作共用。按行校验 ASCII 边界与 XOR 后再解释 GGA、RMC、GSA、GSV、VTG。报告保留发送者标识、原始字段以及行内字节区间，空字段保持缺失，设备报告的无定位状态保留。GSV 的总片数、当前片号和信号标识随原句保留，浏览与查询以实际收到的片为单位。输入和输出有界，坏行保留定位且不影响其他行。随包动作沿用会话读取授权，工作台在本地解析粘贴样本。 [u-blox M10 接口说明第 2 章](https://content.u-blox.com/sites/default/files/documents/u-blox-M10-SPG-5.30_InterfaceDescription_UBXDOC-304424225-20395.pdf)

AT 模板分析已接收文本。显式提供一条在途命令时才关联最终结果，按所选 ATV0/ATV1 解释基本代码。注册状态按查询响应和主动上报各自的字段形态区分。无法判定归属的行保留原文。SMS 多行报文先确认负载边界，缺少可验证边界时保留后续原文，避免把短信正文中的结果词当成命令终态。建立数据模式的结果后保留原始数据。工作台与随包动作共用解析函数，随包继续沿用会话读取授权。 [ITU-T V.250](https://www.itu.int/rec/T-REC-V.250-200307-I) · [3GPP TS 27.007](https://www.etsi.org/deliver/etsi_ts/127000_127099/127007/18.07.00_60/ts_127007v180700p.pdf) · [3GPP TS 27.005](https://www.etsi.org/deliver/etsi_ts/127000_127099/127005/18.00.00_60/ts_127005v180000p.pdf)

JSON 与 YAML 定义进入同一版本化字段校验。工作台显式选择格式，Node 动作的 `definitionFormat` 缺省为 `json`。校验保留字段路径和从 1 起算的来源行列。输入限为单个有界数据文档，拒绝重复键、标签、锚点和别名。YAML 使用锁定的 `yaml@2.9.1`（ISC）浏览器入口，WebView、浏览器和签名 Node 插件共用解析器，无原生依赖或安装脚本。发行包携带对应许可。

桌面定义导入沿用原生文件选择器与 Host 的单文件读取授权。选择时检查类型和大小，工作台用同一文件引用、长度及摘要核对读取结果，并严格验证 UTF-8。通过读取校验的文本作为编辑底稿，语法或字段错误可在工作台直接修正。文件读取期间的本地编辑保有优先权，关闭面板或切换 Host 代次会停止等待。验收覆盖取消、内容变化、超限和晚到结果。

工作台分帧面板以当前 Host 实例和会话代次登记表单及结果。扫描沿用目录检查和独立 Operation，读取终态关联的插件结果文件时核对页范围、同一引用和摘要，再验证帧的源区间。关闭或切换会话取消本地等待，Host 保有已接纳操作的结算责任。验收覆盖无可用插件的入口、授权失败、续页和晚结果。

派生留存峰值由持有样本的 Host 留存层记录，读页峰值来自实际输出租约。通过现有 `host.metrics` 查询两个预算，无需启动采样任务。进程 RSS 仍从操作系统或实际 Node 进程采集。

桌面插件管理复用 Host 的安装、来源和运行快照。明确的本机管理操作使用封闭的原生意图类型，来源及执行信任写入使用独立的用户控制连接。安装、启停和卸载沿用桌面业务身份，显式管理意图按需取得 Host 目标的 `plugins.manage`，安装包的读取权限仍由文件选择入口按对象授予。界面通过业务连接观察 Operation，按当前摘要与 revision 写入，离页仅停止观察。验收须分别核对普通身份无法确认执行信任、显式本机意图提交成功及实时运行状态。

桌面安装列表使用 Host 从清单生成的名称、版本和安装状态，展开后显示来源和可用操作。来源签名的显示同时对照安装收据和当前来源信任。确认执行时使用经摘要校验的清单，显示所请求能力和本机执行风险，确认后仍需显式启用。界面用本地化的提示反馈失败。Host 请求、回执与验收证据继续记录用于复核的摘要和操作标识。

签名主题由安装内容校验读取限长 JSON，并以已登记的配置入口和归档摘要绑定主题。Host 仅发布固定颜色字段。桌面与配对浏览器从本机 Host 读取已启用主题，通过共享设置 revision 保存选择，基础强调色保持独立。当前连接或包登记失效时回到基础配色，局域网会话不会切换外观来源。

### 随包 Node 插件

首方分帧包使用公开 SDK 和通用签名包格式。Host 可执行文件锁定分帧包的 ID、完整归档摘要与发布公钥，并从自身内嵌的归档建立内容证明。产品信任仅覆盖该份归档。包内声明、同目录文件和普通来源登记均不提供首方身份。同一源码的开发和发行构建使用同一份已签名输入，发行时由应用和组件验证链承接发布身份。

首次安装在 Host 持有 profile 的独占锁后走既有校验与原子提交。安装记录与一次性登记标记同事务写入，标记在卸载后保留，并独立于旧安装文档格式。已有同 ID 用户安装时只保存标记，明确停用或卸载后重启也尊重原决定。注册权仅覆盖当前安装的准确包与当前 Host 实例，执行动作仍按调用者对目标会话的权限。若改用普通市场来源自动确认，发布密钥的信任范围会扩大。首方版本升级需要按随新产品交付的精确归档另行验收。

共用 SDK 源码变更后，综合脚本分别重建所有受影响的首方入口并核对编译、清单与归档摘要。Modbus 主站和从站从 0.1.0 升为 0.1.1，以同步共用事务获取代码。动作 ID、权限和数据版本沿用原值。两个原签名归档各自以原登记标记加入已知前驱，复用现有的精确来源、版本和启用状态检查。验收核对旧版启用、停用、卸载的配置状态，以及新版原生 Host 实际执行主站事务和从站应答。

验收核对源码编译产物与归档一致、压缩包摘要和签名均有效。隔离 profile 首启应无需手动导入，同时覆盖替换归档、伪造同名来源、无会话权限、重启、停用、卸载和恢复。正式发行还需在断网安装后从产品入口验证。

首方图表使用独立包 ID `swb.builtin.chart` 与自身的采样、视图和 SVG 动作。共享实现可同时提供外部签名参考包，两个实例沿用各自的安装来源、执行信任和撤销流程。首方样本的派生位置及导出结果沿用会话读取授权。安装收据和组件清单都记录准确归档摘要，归档签名覆盖后端、清单和视图的三个资源。

签名视图的编译输入限定为视图通道实际交付的会话快照、Raw 批次、派生页及相应封套。校验器随 Rust 契约生成，保留会话归属、游标、错误和来源校验。工作台和 Host 的通用 RPC 继续使用全量校验器。验证同一视图源码在增加无关 RPC 结果时生成相同字节，并从准确包版本重新签名。升级检查前驱的归档摘要和来源签名，复验已启用、停用和卸载三种用户决定。CI 继续核对重建脚本、归档内容和签名描述。

## 安全与恢复

本机 IPC 保护当前用户的实例，不抵御同账户恶意进程。普通客户端默认只读元数据；授权、执行确认等用户控制走专用入口。同一同步阶段可共享授权快照，不能跨异步等待沿用。文件、目录订阅、媒体分段和最终 writer 都检查实际目标及当前来源权限。CSP、Tauri capabilities、路径验证与资源预算各守自己的边界，见[安全规范](./conventions.md#安全)。

插件视图读取绑定业务目标及插件运行代次的打开回执。Raw 视图须等待操作成功，派生视图可在取样操作运行中打开。资源读取使用实际登记的视图、验证过的归档资源索引及当前授权，重新启用后须重新打开视图。资源分段读设独立并发上限。桌面使用独立 Wry WebView 承载可信壳，包内容在另一来源的 sandbox iframe 中运行。可信壳核对 iframe 实例与打开时的一次性标识，通过专用端口交付快照和原始流。包内容只能确认当前批次，原生请求上下文留在桌面桥内。

每个终端视图持有独立 Raw 连接、cursor 和 credit。工作台和视图使用 Host 宣告的读取队列预算，计入编码空间与未确认批次，能交付最大合法 TX 事件，在途额度另行限制。原生渲染器在锁外隐藏初始化，显示与连接移除共用桌面桥锁，显示前复核发起文档及 Host 代次。交付前复核授权与代次，包确认当前批次后才继续。撤权、iframe 重载、调用取消或文档结束时回收视图资源。连接失效时桌面主线程销毁绑定窗口，Host 继续持有会话与录制。重开从当前留存窗口恢复，过期游标报告缺口。 [终端参考包验收](./acceptance.md#终端参考包验收)

Windows 的隔离插件视图和主窗都启用 WebView2 页面缩放快捷键，按原生桌面场景核对焦点与可读性。

打开的浏览器视图随工作台语言更新，桌面视图取本地 Host 已提交的共享语言。可信壳只向握手时明确订阅的插件端口发出 `en` 或 `zh-CN`，已安装的旧插件继续使用打开时的设置。语言通知沿用视图的读端口，读取窗口、游标和批次确认各自保留。插件可据此重绘当前标签，设备解码由原有会话数据路径负责。

桌面桥把当前 Host 的目录变更转发到所属窗口，通知只携带桌面连接代次。窗口用当前 Host 身份重读目录和动作权限，分页固定目录版本，忽略被更新通知取代的读结果。重新启用插件时在同一窗口恢复目录入口。

派生视图使用发起窗口的 Raw 请求通道，每个视图持有独立读页位置。Host 查询绑定打开视图的采样 Operation 及会话代次。桌面桥在读页前和交付前复核视图授权，可信壳等当前页确认后再拉取。桌面连接按插件保留最近打开的派生任务引用，在同一归档、视图和会话代次重开时恢复留存样本，遇到缺口时断开曲线。

## 更新与分发

应用、协议、目录和数据格式分别版本化。Rust updater 验证下载，在安装前协调各窗口和在途工作。公钥编译入安装包，可写部署配置仅能更换受控 HTTPS 镜像或禁用更新。桌面、Host、CLI、MCP 与固定 runtime 按同一发行版本交付；组件绑定、签名与启用条件见[分发契约](./contracts/runtime-distribution.md)及[构建与发布](./development.md#构建与发布)。

桌面设置发起的更新在下载验签和窗口确认后，通过本机用户控制入口请求 Host 正常关停。旧 Host 完成后台结算、撤下监听并完成存储检查点后，在持有实例锁时原子写入受保护的关停回执。更新入口持锁核对已认证的 Host 身份、代次和回执。重试沿用这一检查，只有首次使用的 profile 可以直接预约实例锁。

Windows 在关停前观察已认证的命名管道对端，回执绑定 PID 与创建时间。安装准备持有实例锁，先写待定记录，等待实际退出，再保存绑定回执的退出码。调用方取消等待后，观察任务继续持锁直到退出核验结束。重试沿用已观测结果，失败或未知结果引导用户从当前安装重启 Host。Windows 更新器启动独立安装器后会退出。当前用户版 NSIS 提供独立的套件暂存入口。协调进程须先将已验签的安装器放入独占的同卷暂存目录，再等到实际进程退出。暂存入口核对并持有目录句柄，只释放套件文件与卸载程序。安装协调进程、跨进程锁交接和注册信息提交仍待接入与实装复验。 [安装与发行验收](./acceptance.md#安装与发行验收)

Windows 当前用户版 NSIS 独立验证工具先验证 minisign 签名及发布版本，再从同卷私有目录执行固定暂存参数。发布侧用 `file:serial-workbench-nsis-stage-v1.exe` 声明测量用途，在隔离目录对实际安装器输出计算完整套件摘要。随后为同一安装器签出 `file:serial-workbench-nsis-stage-v2-<SHA-256>.exe`，让可信注释同时绑定套件摘要和版本。v2 核验在安装器真实退出后对整个暂存目录重新计算摘要，匹配才产生供换入使用的收据。停用的发布模板在收集阶段复验签名，并用同一签名生成 Windows 更新清单和草稿签名资产。产品更新入口仍待接线。

套件切换由安装目录外的协调进程执行。它接收本次签名暂存操作的 ID 和经核对的新旧完整套件摘要，取得同一 profile 的实例锁，再校验旧 Host 的退出证明。用原操作 ID 重开验证器时报告已有终态。换入失败后尝试恢复旧套件，调用方收到失败并保留回执。

带旧前台进程的换入请求先按 PID、创建时间、当前用户 SID 和安装内的实际可执行文件打开稳定进程句柄。确认身份后才结算旧 Host。取得 Host 实例锁后等待旧前台进程正常退出，再开始改动安装目录。等待超时或退出码非零会结束本轮换入，旧套件可继续使用。

当前用户版 NSIS 桌面更新从正常入口获取签名安装器，暂存及复验通过后，在安装目录旁的同卷私有目录复制当前桌面程序。通过这一副本进入无窗口协调模式，父进程只在接到持锁就绪回执后才请求正常退出。提交成立后，协调器释放锁并用同一 profile 启动新桌面。换入失败而恢复成功时，协调器核对现有套件摘要后重启匹配的版本。协调失败保留同轮证据以供诊断。便携、MSI 及其他平台沿用原有安装入口。

当前用户版 NSIS 的原路径升级沿用已有安装注册身份。换入意图同时绑定旧套件和新套件的摘要、卸载项版本与容量预期。更新须从已存在的当前用户卸载项核对安装位置、主程序名和卸载程序路径，随后只写应用列表的版本与容量。深链、快捷方式和卸载命令沿用相同路径。目录换入与注册更新完成并核对后才确认提交。进程中断时，用同一认证意图恢复两类状态，发现第三方改动时保留证据供诊断。

恢复入口可用当前 profile 与原安装路径发现中断操作。协调进程持实例锁读取各次意图的签名，核对文件名、物理安装位置及 Host 代次后才恢复唯一待定事务。已提交或已恢复的历史收据仍按操作 ID 查询。歧义、签名损坏或代次移交使本轮恢复停止。

客户端效果发起的更新先交给已登记的本机桌面。桌面下载验签、取得相关窗口同意并复核更新策略后，通过原本机控制连接提交准备请求。Host 复核该连接、目标、代次、投递、原始授权和持久运行中的操作，再停止接纳及结算录制和后台任务。屏障完成后，Host 再次验证原始授权和接收窗口，然后确认准备。保存草稿、推迟更新和下载失败都发生在 Host 结算之前。准备回执与安装结果分别确认，旧桌面或 Host 不能沿用缺少准备阶段的安装效果。混装时旧 Host 仍可能先停止录制，推迟更新的录制保证适用于同版桌面与 Host。

## 关键取舍

接收区上下文从当前显示记录解析原事件引用，并用既有原始字节映射读取 HEX 选区。时间书签只保存引用和时间元数据。分屏切换显示模式后按同一条引用重定位。发送预览固定实际会话及修订，用户确认时再验证选区、当前目标与可用性，随后走现有 Host TX 接纳和终态路径。复制和查看保留只读路径。窗口级书签与源绑定，失去原记录后明确显示无法定位。

多端口广播由工作台组装同一 Host 内的显式目标列表，冻结最终编码字节、每个会话代次及会话修订。复用原有共享 `session.tx` 接纳、授权、排队和取消契约。各目标并行接纳，组内保留每个已接纳操作的引用及终态。实际端口节奏继续由各自 TX 仲裁决定。跨端口控制使用一组独立请求，故障或未知接纳分开显示，重查已有操作只读取原回执。

CLI 的无头批次使用同一已认证 Host 客户端与操作目录。附着模式仅等待已有 Host，离线模式由 CLI 以明确的 profile 启动同套独立 Host，并核对附着得到的本机进程身份和实际子进程。离线进程持有私有输入管道，管道关闭后走 Host 正常停机。批次使用普通 CLI 身份与既有授权，不引入另一个运行时或装载任意脚本。

批次按顺序等待真实终态，上一动作失败或实际发送不完整时停止调度。首次 Raw 步骤建立一条附着于同一控制连接的通道。后续 Raw 步骤使用同一通道，Host 每次核对当前授权。连接随批次退出释放，录制搜索游标归原通道，后续批次重新开始。输入先校验，写入前保存 Host 签发的请求上下文。结果保留已提交请求 ID、已观察的操作及此前步骤。期限结束时停止等待。主动取消仅向本批次已确认的在途操作请求停止，真实终态可以用原身份恢复查询。离线模式还确认自有 Host 退出并保留 profile。

独立 Host 换取多客户端共享持口和无头任务，代价是实例身份、权限与整套升级必须协调。Tauri 复用 Web 界面但把系统提交留给 Rust，故浏览器测试不能替代 Native。可信 Node 让内置和市场插件共享作者接口，代价是必须把代码执行信任与设备 API 授权分开；页面不是后台的生命周期所有者。

## 系统串口与 PTY 能力

会话模板是工作台针对所选串口、PTY 或虚拟串口的打开参数和工具入口。预置声明波特率、数据位、校验、停止位及流控，保留这台设备的超时和重连间隔。工作台仅在操作者确认打开时把参数交给原有 Host 入口，并按成功回执记录实际配置。已经打开的会话保持其当前配置。STM32 终端与 AT 应答检查可直接预览，Modbus RTU 从站的实时入口要求对应动作已登记，且当前会话、参数和写权限符合要求。缺动作时进入现有插件管理，来源信任和执行确认按原流程处理。模板切换、打开和导航使用工具草稿的离开确认，角色工具按 Host 附着与会话代次归属。

故障向导把「打不开」绑定连接栏所选设备及其失败回执，把「乱码」「丢数据」「断连」绑定当前活动会话。会话证据按 Host、会话和代次筛选。乱码复用有界接收样本和编码识别，只参考当前配置修订的 RX，明确显示证据来源和样本长度。显式应用只改当前视图解码和显示。丢数据分别统计读端缺口和采集流报告的来源缺口，实际线缆或设备丢包须结合对端计数。断连显示 Host 的重连状态和错误码。重试与返回查看由用户触发，并保留正常端口打开与会话权限检查。

系统串口由独立 Host 的设备目录提供。目录返回不透明 `deviceId`；打开操作解析当前目录与绑定后，才把受信的系统定位符交给原生提供器。COM 编号、tty 路径和枚举顺序都不是稳定设备身份。目录刷新、stale 与重连规则由设备服务维护，平台提供器只读取 OS 事实。

设备目录每次只执行一轮枚举。`device.refresh` 等待调用开始后启动的枚举完成，多次请求可共用随后的一轮。关停唤醒等待者并返回 `HOST_CLOSING`。

### 配置与读回

产品保留 5/6/7/8 数据位、五种 parity、三种 stop width 和四种流控。平台不能表达的组合返回 `UNSUPPORTED_CAPABILITY`；驱动修改了请求值时，配置回执保留实际读回，TX 门控保持关闭。打开时只有全部字段确认一致才返回成功。

| 配置              | Windows                           | Linux                                   | macOS                                          |
| ----------------- | --------------------------------- | --------------------------------------- | ---------------------------------------------- |
| 5/6/7/8 数据位    | DCB，随后 GetCommState            | termios2，随后 TCGETS2                  | termios，随后 tcgetattr                        |
| none/even/odd     | 支持编码与独立读回                | 支持编码与独立读回                      | 支持编码与独立读回                             |
| mark/space        | DCB MARKPARITY/SPACEPARITY        | CMSPAR，依驱动读回                      | 通用 termios 无对应表达，明确拒绝              |
| 1.5 stop          | 仅 5 数据位组合；6/7/8 明确拒绝   | 通用接口无法与 two 准确区分，明确拒绝   | 通用接口无对应表达，明确拒绝                   |
| 2 stop + 5 数据位 | 明确拒绝                          | 明确拒绝物理宽度歧义                    | 明确拒绝物理宽度歧义                           |
| RTS/CTS           | CTS 输出门控与 RTS handshake      | CRTSCTS                                 | CRTSCTS                                        |
| DSR/DTR           | DSR 输出门控与 DTR handshake      | 通用 termios 无双向 handshake，明确拒绝 | CDTR_IFLOW 与 CDSR_OFLOW，依驱动读回           |
| XON/XOFF          | 双向软件流控                      | IXON 与 IXOFF                           | IXON 与 IXOFF                                  |
| 任意 baud         | DCB 的 u32 范围，依驱动接受与读回 | termios2/BOTHER 的 u32 范围             | termios 或 IOSSIOSPEED；无法独立读回时拒绝确认 |

读写等待和重连间隔是 Host 策略字段，由 Host 保存；它们不伪装成硬件寄存器读回。数据通路关闭 echo、换行转换、strip、NUL 丢弃和字符替换。RTS/CTS 模式占用 RTS，DSR/DTR 模式占用 DTR；手动改变已被流控占用的线返回 `CONTROL_CONFLICT`。

### 原生资源与排空

打开、读写、取消与 close 的责任归原生 owner；等待超时不能提前释放句柄或复用端口。驱动 drain 与最后停止位、USB FIFO 和物理线空闲不是同一事实。自动 TX 时限据最终字节和线路参数估算，流控暂停仍可能超时；历史 TX unknown 不改写，只有实际控制线已清除、原生清理成功、线程已回收才释放关停责任。

录制内搜索（LOG-10）沿用只读回放的文件守卫、已验证记录索引和摘要。Host 分页检查索引定位的记录，只将命中的录制序号和零基字节范围提供给客户端。RX 字节在同一来源、配置及连续范围内可跨记录匹配。TX 搜索针对已保存的最终发送意图，跳转后继续查看对应回执。缺口、配置或生命周期边界结束匹配。数据报片段只在同一报文连续时合并。

搜索推进和回放读页、速率及断点各自持有游标。搜索按 Raw 连接和回放会话保留有界匹配状态。每页校验本批记录，在提交页与游标前重新核对文件权限、原授权和连接。停止搜索、关闭回放或断开 Raw 后释放游标。重新授权并开始搜索时，Host 清退本连接上已经失效的原游标。工作台沿用回放读权限观察，在授权失效时收回命中及搜索定位。接收方凭记录序号跳转到回放并保持暂停。搜索重启从索引首条开始，换源或索引损坏沿用录制验证与恢复。搜索索引采用原有卷地址及长度，文件内容和回放格式保持兼容。验收覆盖大录制、跨页和跨源、缺口、取消后重试、来源替换及首次和重建后定位一致。

多源录制容器以本地 Host 的入队时钟保存相对间隔。录制和回放继续保留每条事件的源时钟，跨源回放用已保存在卷内的录制时间。0.1 容器保持原格式，只在可比的源时钟之间按原速播放。恢复和追加分别保留原容器版本和已验证时间，公开记录引用的结构保持一致。 [录制容器](./contracts/capture-container-v0.md)

### 控制与诊断

桌面诊断包采用带格式版本和采集时间的 JSON。预览、复制和保存使用同一份已脱敏报告。它包含系统平台、桌面运行状态、同一已提交修订的语言和网络等运行偏好，以及有界的应用日志尾部。日志按完整起始行裁剪并走现有脱敏入口，日志路径无法安全读取时以 `null` 表示并保留其余报告。保存沿用原生文件对话框和原子写入。

- Windows 使用 SetupAPI 枚举 present Ports，读取受控 PortName、说明、厂商、硬件标识、拓扑及驱动信息；Linux 读取 sysfs tty 与 USB 祖先属性；macOS 使用 IOKit IOSerialBSDClient 与 USB 注册表属性。
- 序列号缺失不补默认值。Windows 不把任意实例 ID 的末段当序列号；目录还会检查候选唯一性和拓扑变化。
- DTR/RTS、BREAK、purge、队列采样与 CTS/DSR/RI/CD 输入采样通过平台 API。输出调用成功表示驱动接受了请求；物理电平与对端收到 BREAK 需要硬件验证。
- purge 无法对应逻辑流偏移时报告未知丢弃范围，不编造字节偏移。Windows 接收溢出会产生明确错误；Unix 的普通 tty 接口没有统一的溢出计数，持续无损能力需结合实际驱动验证。
- 原生错误保留稳定 code 与 `details.osCode`，不把任意路径或推测的占用进程写入错误文本。

平台行为按目标 OS 的 `serial_backend` 和 `pty_roundtrip` 验证；PTY 不证明真实适配器速率、CTS/XOFF 阻塞或 BREAK 电平。硬件范围见[平台目标](./requirements.md#平台目标)。
