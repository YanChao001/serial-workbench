## 性能证据

| 可重复输入                                     | 修改前                | 修改后                         |
| ---------------------------------------------- | --------------------- | ------------------------------ |
| 128 条操作历史中一条 revision 更新             | 128 次详情 RPC        | 1 次；相同或更旧 delta 为 0 次 |
| 一份 Native 状态 delta 进入 SDK                | 2 次完整 schema 校验  | 1 次；错误通道仍拒绝           |
| 两次正常 Raw 消费确认                          | 4 次 credit RPC       | 2 次；耗尽余量另补额度         |
| 三个独立操作观察输入，持续 1.1 秒且结果不变    | 9 次查询、10 次通知   | 9 次查询、4 次通知             |
| 64 KiB 重复前缀、8192 字节查询不匹配，三次均值 | 约 1763 ms            | 约 18 ms                       |
| 64 KiB 单字节密集匹配的搜索结果分配            | 最多 65536 个结果对象 | 最多 2 个                      |

搜索数值来自同机源码比较；其余为边界测试计数，均不代表物理串口吞吐或真实窗口延迟。优化没有扩大队列、减少授权复核或自动重放修改操作。

搜索复现脚本与冻结源码在 `.cache/code-audit/stream-search-benchmark.mjs`，本次三份逐次样本及环境在 `stream-search-reproduced.json`。输入为 65536 个 A，查询为 8191 个 A 加 B，使用相同的 TextEncoder 编码替身；测量时 Rust 工作区仍在后台编译。早先约 858 → 9 ms 的临时观察未保留逐次样本，另存为历史记录，不与本次原始样本混用。

## 编码依赖复核

常用编码转换使用 `iconv-lite@0.7.3`（pillarjs/iconv-lite），自动识别使用 `chardet@2.2.0`（runk/node-chardet），均从 npm 锁定版本与完整性摘要、采用 MIT 许可，无安装生命周期脚本，也不引入原生平台模块。浏览器内置 TextEncoder/TextDecoder 无法完成 GBK 等编码的发送转换，手写字符映射或启发式检测会重复维护成熟能力，因此复用这两个纯 JavaScript 包；收发与搜索复用共享编码入口，自动检测结果仍允许手动覆盖。

浏览器构建显式使用 `buffer@6.0.3`（feross/buffer）和 `string_decoder@1.3.0`（nodejs/string_decoder）提供传统编码依赖所需的 Node 字节/分段接口；两者同为 MIT 许可的纯 JavaScript 包，无安装生命周期脚本，通过 Vite 精确别名接线，不引入通用 Node 系统能力垫片。

传统编码实现按需加载，本轮桌面构建的独立 `legacy-text-encoding` chunk 为 304.58 kB（gzip 162.85 kB），不作为常用 UTF-8 首屏入口同步加载；数字用于记录当前产物成本，不代表新增依赖相对基线的精确增量。依赖清单和锁文件随功能提交，后续升级仍按依赖审计检查来源、许可与构建行为。
