# 代码签名策略（Code signing policy）

本文维护 Serial Workbench 的代码签名范围、角色和启用条件，操作见 [构建与发布](./build-release.md#代码签名)。

## 状态

当前代码签名与发布工作流均未启用，仓库保留可选 SignPath 集成。启用 SignPath 前完成服务申请、门户配置和凭据配置；在 Release 中记录实际签名状态与验签结果。

使用 SignPath Foundation 时，按服务条款公开实际服务方和“Code signing policy”入口，并更新本文的签名提供方、证书主体与权限。

## 签名范围

现有 SignPath 配置签署 Windows x64 NSIS 安装包外层，产品名来自 [app.config.json](../app.config.json)。安装后的 exe、MSI 和第三方组件在此范围之外；扩展签名范围时同步 artifact 规则和验签步骤。

其他平台与签名方式见 [代码签名](./build-release.md#代码签名)。代码签名验证系统发布者，Tauri 更新签名验证更新包与版本；先完成代码签名，再签署最终更新包。

## 角色与审批

维护者负责代码评审、发布基线、签名配置和产物核验。启用 SignPath 时，在门户指定审批人并人工批准每次请求。账号启用 MFA，凭据存入受控 Secret，限制为所需项目和策略的权限。

## 构建与签名流程

签名输入必须对应已确认源码、版本和目标平台。核对归档哈希、证书主体、时间戳及平台验签结果，再进行安装和升级验收。具体流程、失败恢复和公开步骤只在 [构建与发布](./build-release.md) 维护。

## 隐私

签名输入为构建产物，提交前排除构建凭据、服务令牌和用户数据。签名服务可能处理安装包、公开仓库标识和请求元数据；启用前审阅提供方的隐私政策。
