# 新 Host 契约索引

本目录是 [重构设计](../superpowers/specs/2026-11-07-serial-workbench-design.md) 的 M0 实施规范，供 M1—M3 实现与合同测试使用。文中的 MUST 语义用“必须”，可选择行为用“可以”。这里定义的是新体系 v0；当前已实现能力仍以 [产品范围](../product-scope.md) 与 [架构](../architecture.md) 为准。

| 文档                                          | 唯一维护的职责                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------- |
| [Host v0](./host-v0.md)                       | wire 基元、身份与版本、动作/查询/订阅信封、权限、去重、持久状态与客户端边界 |
| [流与操作 v0](./stream-and-operations-v0.md)  | 会话与租约、真实任务结算、原始事件、发送与控制、录制/回放和失败向量         |
| [Node 扩展 v0](./node-extension-v0.md)        | 正式包、后台与 Web UI、贡献、监督和执行信任                                 |
| [runtime 分发基线](./runtime-distribution.md) | Node 四目标来源、完整性、许可、固定布局与离线验收                           |

总设计与 [功能矩阵](../superpowers/specs/2026-11-07-serial-workbench-feature-matrix.md) 决定产品范围；本文组补齐可实现字段和失败语义。M0 不生成新的运行时，也不宣称独立 Host、浏览器、LAN 或 Node 已交付。M1 将这些字段落实为 Rust DTO、校验器和 handler，Rust 成为类型与运行时 schema 的权威，客户端绑定与 Node SDK 从同一来源生成，禁止另维护手写 TypeScript 协议。动态插件输入输出 schema 注册到同一能力目录，公共信封仍由 Host 定义。

v0 的初始协商值为 `protocolVersion: "0.1"`，只支持精确匹配。M1/M2 如需破坏性改动，更新协商值、生成物、调用者和向量；不能靠忽略必需字段维持表面兼容。M3 通过 [冻结检查](../superpowers/specs/2026-11-07-serial-workbench-design.md#m3-契约冻结检查) 后才确定 v1 支持窗口、相容扩展和退役政策，并落实总设计要求的新体系同主版本可选字段与能力协商。应用版本、协议版本、目录版本与文件格式版本分别管理。

新体系自身的 revision、未来格式拒写和失败证据保留适用于后续版本演进；Host 客户端与 LAN 的互通按上述阶段建立支持窗口。

验收向量是后续测试输入要求，不是 M0 的运行结果。本文的初始保留期、队列限额协商和精确 v0 版本是 M0 工程选择；实现验证发现问题时，同步修订合同与调用者。数据恢复保持原件、未来格式写保护与失败证据，遵循 [安全规范](../security.md)；一次实际验证的环境与结果写入对应 PR。
