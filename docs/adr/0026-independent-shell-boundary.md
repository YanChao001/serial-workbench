# 26. 将 Serial Workbench 定义为独立产品空壳

- 状态：已采纳
- 日期：2026-11-06
- 相关：[产品范围](../product-scope.md)、[架构说明](../architecture.md)、[测试规范](../testing.md)

## 背景与取舍

Serial Workbench 需要从明确、有限的应用边界继续开发。保留业务展示页面、默认示例插件及其原生命令，会增加导航、权限、持久化和验证范围，并让界面暗示尚未实现的产品能力。只隐藏入口仍会留下可调用路由、命令及打包内容。

## 决策

应用只提供三个主导航：首页、插件中心、设置。首页保持空白；诊断与恢复归入设置。插件页面及独立窗口继续使用受控内部路由，不增加业务导航。

实际删除业务展示页与专属源码、路由、命令、文案、样式和资源，同时清除相应原生注册、权限、默认包及验证场景。移除虚拟设备与记录回放示例、笔记 SQLite、HTTP 和系统能力展示、文件编辑与扫描任务，以及自动安装或恢复默认插件的入口。应用偏好由设置文件维护；插件私有存储、图库和媒体分别保留自身数据与版本保护。

保留窗口、主题、中英文、皮肤壁纸、插件宿主、安全边界及更新框架。插件中心初始为空，插件由用户安装；后续串口业务另行定义。

应用更新、市场签名与工作流的启用状态由 [产品范围](../product-scope.md) 维护。

## 影响与验收

源码、文档、默认资源和验证范围以空壳实际行为一致收敛。浏览器继续复用前端并使用 HashRouter，原生能力由环境门面控制。

验收检查三个主导航、空白首页、插件空态和设置入口，以及旧业务路由、命令和默认包的清理结果。设置的原子写入、迁移、冲突和未来格式保护，窗口与插件的权限、取消和回收规则继续覆盖。

新增业务时，在产品范围与所属架构中定义功能、状态、权限和失败语义，再接入页面与命令。
