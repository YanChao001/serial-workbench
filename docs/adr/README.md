# 架构决策记录（ADR）

本目录记录 Serial Workbench 当前采用的技术选择与理由。当前功能范围见[产品范围](../product-scope.md)，契约和操作步骤由[文档索引](../README.md)中的指南维护。

## 记录门槛

核心技术、跨层契约、数据归属或分发方式存在实际备选，且后续维护者需要理解选择理由时才写 ADR。普通功能、样式和缺陷修复在 issue / PR 中说明；跨模块本身不要求新建记录。

ADR 记录问题、选择、代价与复查条件，不复制协议、实施清单和测试结果。决策实施时同步当前架构或所属指南。

## 命名与状态

文件名使用四位递增编号和英文短名，例如 `0026-independent-shell-boundary.md`。编号用于稳定引用，删除后也不复用。

状态为 `提议中`、`已采纳`、`已废弃` 或 `被 000N 取代`。结论变化时记录新的选择；局部取代说明覆盖范围并互相引用。保留仍有独有理由的旧记录，失去维护价值的记录可以删除或合并，并同步修复入链。

## 模板

```markdown
# N. 决策标题

- 状态：提议中 | 已采纳 | 已废弃 | 被 000N 取代
- 日期：YYYY-MM-DD
- 相关：[所属指南](../architecture.md)

## 背景与取舍

实际问题、约束和备选方案。

## 决策

当前采用的选择及其边界。

## 影响与复查

维护代价及需要重新评估的条件。
```
