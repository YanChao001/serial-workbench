# 21. 用独立媒体副本保存视频壁纸

- 状态：被 [0027](./0027-shared-host-and-node-extensions.md) 的 Host 文件引用与客户端媒体票据取代
- 适用范围：设置中的本机视频壁纸
- 相关：[图片图库](./0004-wallpaper-library.md)、[架构说明](../architecture.md)

## 背景与取舍

把视频字节放进设置会扩大每次同步；只保存用户文件路径又依赖原文件长期存在。因此视频需要独立的资源归属。

## 决策

原决定以应用管理副本换取对原路径的独立性。M1 的共享 Host 统一管理文件登记与读取权限后，不再保留独立壁纸副本存储和内容 ID 协议；系统对话框选择实际文件并登记固定 ObjectRef，设置保存引用与显示方式，图库保存客户端元数据。文件变更按固定内容规则拒绝，旧管理副本不迁入。

将视频字节排除在设置之外、通过有界范围播放、不开放任意路径的理由继续成立。Native 使用属于窗口实例和连接代次的临时票据，每段通过 Host 复核原引用；并发任务和响应正文使用独立预算。播放静音循环、随活动状态暂停，失败保留选中引用并提示。浏览器临时 Blob 只用于当前实例预览，不能伪造共享 Host 引用。具体生命周期见 [架构说明](../architecture.md#数据存储)。

## 影响与复查

设置归档只包含引用，不自动包含原文件。需要转码、离线副本、跨设备同步或媒体随备份迁移时，重新评估 Host 文件归属与归档格式；目标平台的解码和长期播放仍需实际验证。
