# 27. 共享独立 Host 与可信 Node 扩展

- 状态：已采纳
- 日期：2026-11-07
- 实施状态：M0 删除旧扩展栈并建立合同；独立 Host 与 Node 后台分别在 M1、M2 实施。
- 相关：[重构设计](../superpowers/specs/2026-11-07-serial-workbench-design.md)、[Host 合同](../contracts/host-v0.md)、[流与操作](../contracts/stream-and-operations-v0.md)、[Node 合同](../contracts/node-extension-v0.md)。

## 背景与取舍

GUI、浏览器、CLI、MCP 与插件需要操作同一设备、任务和状态，录制与长任务需要在关页后继续。以桌面窗口为资源所有者会让无头和共享访问依赖窗口生命周期；独立 Rust Host 增加进程与发布协调成本，但能明确唯一持口者、发送仲裁、权威原始流与任务结算。

完整终端、协议、脚本、分析和专业设备适配需要 npm 生态、native addon 与外部工具。继续扩展旧 Wasm 固定效果及自定义界面协议会保留两套执行、包和权限模型。本轮选择可信 Node，从首版重建扩展接口；不提供旧软件执行兼容，不为旧 UI 或 SDK 增加适配层。

## 决策

每个用户数据配置使用一个独立 Rust Host，GUI/CLI/MCP/浏览器与 Node 共用能力目录、handler、状态和任务合同。Rust 持有系统串口及原始录制；插件后端的实际句柄可位于受监督 worker，逻辑会话和仲裁仍归 Host。公共基座在所有插件关闭时保持可用。

内置与市场插件共用可信 Node 主宿主、正式离线包和生成 SDK。主宿主负责轻量激活与编排，脚本、持续解析和重计算放入可终止 worker/子进程；独立监督器恢复主 Node 时保留 Rust 自持资源。后台拥有业务状态，隔离 Web UI 只处理呈现和草稿；业务关页继续，重新附着从快照恢复。动作、查询、配置、状态与 GUI 定位同时提供，人工与 MCP 走相同授权。

可信 Node 具有当前 OS 用户权限；API 授权与任意代码执行信任分别维护。首次启用审阅来源与执行权限，范围内普通操作不重复确认，同源相容升级保留已有信任，来源/身份或执行范围变化重新确认。签名证明来源和完整性，不能代替用户信任。安装包携带预构建依赖与平台资源，不在用户设备执行依赖安装脚本。

旧 Wasm 运行时、依赖/vendor、包格式、SDK、桥、命令、示例、测试、市场链和旧格式迁移入口在 M0、进入 M1 前删除。旧授权、缓存和旧插件数据不迁入新体系；用户内容静置保留，新数据用独立目录。个人设置、公共壳、原子存储、revision 和失败保留等合理职责继续使用，旧专属协议随实现删除。

## 与公共壳的边界

[ADR 0026](./0026-independent-shell-boundary.md) 继续维护公共壳与尚未实现业务的入口边界；其中空白工作区是当前基线，随着本决定的功能交付更新产品范围。旧插件专属决策已随基座清理删除，删除清单与验证证据保留在基座 PR；本记录只维护新体系的长期取舍。

## 影响与复查

独立 Host、Node 与客户端需要一致的身份、版本、任务记录、资源预算和整套组件升级机制；三平台需要随包 runtime、native addon 与工具的许可、签名和离线验收。共享可信 Node 降低包接入成本，但主宿主挂起会中断其中多个插件任务；原始采集与监督通道必须独立。

当正式参考插件无法仅用公开 SDK 完成业务、主 Node 故障侵入 Rust 录制、浏览器 UI 依赖桌面全局、代码执行权限被设备授权隐式带入，或某平台无法离线分发时，重新评估相应边界。M2 验证真实包与故障场景，M3 通过跨入口/版本/后台升级场景后冻结 v1。字段、验收向量与 runtime 精确来源分别维护在合同与分发基线，ADR 不重复定义。
