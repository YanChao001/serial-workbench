# 串口工作台界面重组设计

状态：用户已确认。2026-11-08。用户在查看实际样稿截图后明确“按照当前gui设计继续，我现在对gui没意见”。本设计落实已确认 M1 功能的呈现与接线，实施沿用 M1 的并行分工、集中里程碑和验收要求。

## 意图与依据

首屏应让调试者选择设备、查看接收内容和发送数据。用户已指出当前界面偏向内部状态面板，要求借鉴 `serial-workbench-old` 的设计理念，以 `tauri-desktop-starter` 实际 GUI 为基准，充分使用其主题、透明背景、磨砂和统一控件。

参考以两个本地项目的实际源码及用户提供的旧工作台截图为准。旧工作台的连接参数就近、接收区占主面、发送器始终可达是展示职责；旧 API、状态模型、存档和插件体系不进入新项目。开源终端只作为标签、收发与选项组织的参考，不引入它们的配色或依赖。

## 方案与取舍

采用用户已选择先制作样稿的方向：保留 starter 外壳与导航，顶部连接条、中央接收区、底部发送器，辅助操作从就近入口展开。现有 Device/Capture/Metrics 常驻第二侧栏以及两栏默认展开任务区会挤压收发空间，不能满足本轮要求，因此不继续沿用。接收工具选项在阅读区附近，设置和恢复仍归现有设置入口。

样稿证明了布局、模拟交互与材质组合可行；其模拟设备、字节、计数和录制状态只供设计审阅。正式实现必须接当前 Host、真实 Operation 与生成 DTO，不能保留模拟状态机或把它们作为生产回退。

## 布局与导航

```text
starter 标题栏 / 可折叠应用导航
┌ 工作区名 / 设备选择 / 参数摘要 ▾ / 连接或断开 / 更多 ┐
│ 会话视图标签                                      │
│ Text / HEX / 搜索 / 跟随 / 录制 / 日志 / 清空      │
│                                                  │
│ 接收阅读区，使用剩余高度并独立滚动                 │
│                                                  │
│ 当前收发与录制摘要                                │
├──────────────────────────────────────────────────┤
│ 发送格式 / 行尾 / 字节预览 / 文件发送              │
│ 发送草稿                                  发送   │
└──────────────────────────────────────────────────┘
```

- 工作台路由显示“串口工作台”，图标、命令与导航名称复用路由和词典来源；保留 HashRouter、懒加载与既有命令入口。
- 为工作台声明占满可用内容区的路由布局，移除其普通文档页最大宽度和整页滚动；设置等文档页保持原有布局。布局元数据维护在 `src/routes.tsx`，外壳统一消费，不在多处匹配路径。
- 应用导航沿用当前折叠、调宽与持久化机制。本设计不强制改用户的导航偏好，也不再默认添加第二个设备侧栏。
- 接收区随剩余高度伸展；发送器始终可见，包括未连接时。禁用发送时就近显示原因，草稿仍可编辑。回放会话按既有只读语义呈现。
- 按工作区容器宽度收纳参数摘要和次要文字，必要时连接条换行；保留具名按钮、键盘入口和可达性，不以减小正文字号或整页横向滚动塞入控件。

## 材质与控件

直接复用当前仓库从 starter 保留的 AppShell、WindowBackground、独立 window-reading-surface、主题设置和 UI 控件。业务页不另建颜色、透明度或 blur 系统。

| 区域                       | 材质与组件                                                              |
| -------------------------- | ----------------------------------------------------------------------- |
| 工作区框架                 | 一层 panel；内部布局、标签与分组 transparent，以分隔线表达关系          |
| 接收 viewport              | 单层 reading；行内容透明，不再把整个 editor 包成 reading                |
| 输入与普通动作             | 现有 Button/Input/Textarea/Select/ToggleGroup/Tabs，沿共同 control 规则 |
| 参数、录制、收藏、日志入口 | 现有 Popover/DropdownMenu；需要长编辑或确认时用 Dialog                  |
| 关键阻断错误、恢复失败     | 现有错误与 solid 语义；技术详情展开，不堆到首页                         |

颜色、圆角、字体、强调色与焦点来自语义 token。终端字体消费当前共享终端设置；全局字号和终端字号职责分开，不新造客户端并行存档。RX/TX 除颜色外保留方向或名称，时间/偏移和字节使用可读等宽数字。明暗、高透明图片、纯色、高对比与减少动效沿基座降级策略。

## 操作组织

### 连接、设备与工作区

设备选择、连接/断开与当前连接摘要常显。参数入口展开波特率、数据位、校验、停止位、流控及现有串口控制；请求值/有效值和真实回执保持可查。制造商、驱动、USB 身份证据与最近连接/收藏在设备入口内展示，未知信息明确未知，不编造硬件状态。

工作区菜单提供加载、编辑、克隆、保存和 JSON 导入/导出。编辑可进入 Dialog，保存使用实际 revision CAS；冲突保留草稿并提供重新读取。导入必须先展示预览与差异，再明确应用，不以直接覆盖写入冒充预览。加载与切换不自动连接、发送或运行任务。

日常新建、关闭或调整标签页只影响当前窗口，不立即形成待保存的工作区文档。明确保存时，将当前窗口的视图及布局写入工作区模板；其他窗口继续使用自己的运行布局，不因这次模板更新自动开关标签。

关闭视图和断开真实会话是不同动作，文案及菜单明确区分。未保存草稿继续登记 useUnsavedWork；发送草稿按 ClientState 保存，工作区文档按 Host CAS 保存，局部工具参数可放弃而不虚构保存能力。

### 接收与发送

接收常显 Text/HEX、跟随状态和常用动作；搜索展开为紧邻接收区的搜索条，高级显示选项进入弹层。冻结只停止视图跟随，持续接收和新数据计数保持真实。Gap、边界、重连或回放 seek 不能被显示为连续字节流，UTF-8 半字符按既有 reader 边界清理。

发送器提供当前 M1 的 Text/HEX、行尾与自定义行尾、最终字节预览、显式发送和文件发送。非法输入不能触发 invoke，IME 不触发发送快捷键；快捷键复用命令约束。文件传输的速率、块大小、范围、取消与 Partial/Unknown 回执进入相邻工具面板，不改变实际 Host 语义。

### 录制、回放、任务与诊断

录制状态在接收工具入口及摘要可见，详情展开后提供开始/停止、写入模式、容量/余量、验证/恢复和文本导出。回放的打开、最快/原始时序、播放/暂停/定位与当前来源就近显示。选择路径本身完成本机目标授权，不增加权限管理页面或第二次授权步骤。

操作日志与后台任务按需展开为统一可滚动详情面板。首页只显示进行中数量、当前会话收发/丢失/录制摘要和需要处理的错误；Host 内存、actor、operationId、原始 actionId 等留在详情或诊断，仍可定位。取消停止等待不能显示为已停止或已回滚，结束以真实 Operation 和回执为准。

命令面板从实际 Host catalog 与当前目标权限构建，撤权及时更新。全局 session.tx 可发现性不能代替工作区、设置或文件的目标能力判断。本机新的明确动作使用专用 Native 入口；初始化、订阅与后台重试不自动补权限。

## 实现边界与验收

现有 Host Provider、文件资源、reader、工作区与设置模型保留各自权威，页面只组织视图和草稿。新增或调整 Rust DTO 后由 Root 串行生成并校验绑定；缺少的已确认 M1 契约继续补齐，不以长期“不可用”控件代替交付。独立组件可并行，路由、外壳、词典、共享 Provider 及生成物安排唯一写入者。

正式验收覆盖：未连接首屏；Virtual 实际收发；真实串口配置/控制（具备设备后）；多个视图与草稿；Text/HEX/自定义行尾；搜索/冻结/Gap；文件传输与取消；录制/验证/恢复/回放；工作区 CAS/导入预览/导出；命令和撤权；键盘/焦点/无障碍；明暗与高透明背景；1120×744、880×600及导航展开/收起。

默认使用无头界面检查。真实原生窗口按用户安排的前台时段或独立环境验证。样稿的模拟检查、Windows 无头结果、未测试的真实硬件/其他平台分别记录；没有实际执行的范围不标通过。

具体间距、各弹层宽度、图标选择及组件拆分由实现者在既有基座刻度内决定。实现过程中可据真实渲染调整细节，不改变上述任务组织与数据/权限边界。
