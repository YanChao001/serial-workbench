## 维护规则

同一规则在一处维护，其余文档通过链接引用。README、CONTRIBUTING 和 AGENTS 提供入口；产品范围介绍功能；架构解释职责与数据；开发、测试、发布和排障指南说明操作；ADR 记录长期取舍及理由。

工程文档以中文为主，README 提供英文入口。使用 UTF-8、可读的相对链接和标明语言的代码块；版本、字段、完整命令清单及预算链接到配置或实现。第三方许可证与声明保留原文。

修改行为时同步对应指南、示例和入链。过时内容由 Git 保留历史；仍有效的决策保留理由，改变结论时记录取代关系。一次变更的检查结果写在 PR 或 Release 中。

### 写作与免责措辞

围绕开发者的任务写清功能、操作和结果。优先使用“是什么、怎么做”，每段解决一个问题；产品状态在产品范围维护，具体操作在对应指南维护。

提醒、限制或免责语句先问：**删掉后，读者的操作或判断会改变吗？** 无影响就删除；有影响，写成具体条件、后果或下一步，放在相关操作旁。权限、凭据、删除、数据恢复和许可义务按这一原则保留。

| 常见措辞                             | 处理方式                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| “本文仅供参考，不保证覆盖所有情况。” | 删除，直接说明本文覆盖的功能和步骤。                                         |
| “本地成功不能证明生产环境可用。”     | 在验证结果中记录平台、命令和结果；目标环境需要的检查写入发布步骤。           |
| “不保证取消后操作没有发生。”         | 写清实际语义，例如“取消停止等待，已发出的写入可能继续完成；按回执确认结果”。 |

同一限制说明一次即可。精简时保留实际条件与不确定性，把泛化的“不能证明”“不代表”“不保证”落实为读者需要的信息，而非换词重复。一次变更的验收记录留在 PR 或 Release。

### 事实与链接核对

- **以实现核对事实**：沿实际流程检查页面名称、资源、默认值和数据行为；用实际路径、子模块及忽略规则确认文件存在性。不同操作分别说明条件，例如普通保存、确认重置与隔离恢复。
- **以入口核对命令和覆盖**：核对工作目录、shell、前置条件、脚本参数、测试筛选或收录范围，以及 CI 触发条件。示例使用真实接口和完整参数，帮助入口以脚本支持的选项为准。
- **随变更维护链接**：文件、标题或模块变化时同步入链；跨仓库链接支持独立检出。检查文件路径与标题锚点，区分外链失效和访问受限。
- **按影响验证**：文档检查格式、链接及与实现的一致性；涉及示例或接口时补充对应核对。检查结果写明实际执行范围。
